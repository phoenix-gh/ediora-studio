## core_point（唯一中心，篇幅 ≥40%）

真正让提示词"好用"的不是某个特定场景的模板文字，而是 **STAR 原则**（Situation → Task → Action → Result）——给模型标注四层信息：项目背景、具体任务、技术约束、输出格式。一篇博客园帖子整理 10 个编程场景模板，拆开看每个都是 STAR 的包装。**writer 只需挑 1-2 个亲自验证的模板展开**，不要逐条复述 10 条。

原文开头的"写一个计算订单金额的 Java 方法"→ AI 输出大概率不规范，因为没有背景（S）、没有约束（A）。这个对比本身就够说明问题。

1. **原文**：《程序员最常用的10个AI提示词》，2026-04-29 发表于博客园，作者 苏三说技术。  
   https://www.cnblogs.com/12lisu/p/19948920  
   页面顶栏和正文有 susan.net.cn（Java突击队网）商业推广。

2. **STAR 拆解**：原文把 STAR 定义为：  
   S — 项目背景  
   T — 具体任务  
   A — 技术约束和规范（Java、BigDecimal、Mockito 等）  
   R — 输出格式（注释加或不加、解释先行还是代码先行）  
   每个模板里都藏着这 4 层。

3. **calculateDiscount 方法签名**：`public BigDecimal calculateDiscount(BigDecimal amount, int vipLevel)` —— 原文模板 #2 的示例。AI 按规范生成的单测覆盖：amount 为 null 抛异常、amount 负数抛异常、vipLevel 边界（0 和 5）、正常折扣计算。  
   **如果 writer 亲自复现**：可以把不加 STAR vs 加 STAR 的输出截图放进帖子。

4. **复合索引建议**：原文模板 #7 给出 `WHERE status='PAID' AND create_time BETWEEN '2026-01-01' AND '2026-03-31'`，AI 建议创建复合索引 `(status, create_time)`，并提醒覆盖索引可避免回表。这是一个"给了约束 → AI 给了具体执行建议"的好例子。

5. **原文商业立场**：作者穿插推广了 suan.net.cn（Java突击队网），"更多项目实战在 Java 突击队网"。writer 需注意引用时点出原文的这一面（属于面向 Java 细分受众的付费内容引流）。这对读者也是一种提示。

## 反方/补充观点（≥ 1 条）

1. **STAR 不是银弹**。同一个模板给不同模型（Claude vs GPT-4o vs DeepSeek），输出质量差异仍然明显。STAR 提高了下限但上限还是看模型能力。
2. **过度构造的代价**。对简单任务（如"按驼峰命名把字段列出来"）加四层 STAR 是浪费 token 和注意力。STAR 真正该用的时候是多步推理、多约束输出、需要特定规范的场景。
3. **偏向 Java 后端**。原文模板全系 Java + Spring 生态打样，前端、数据科学、DevOps 场景的读者可能觉得"跟自己关系不大"。writer 可以点一句"换个语言/框架也能套用，但你得自己填充 Action 层的约束"。

## 候选锚点（writer 拿来做"我试了..."的开口句）

> 我把 calculateDiscount 这个方法丢给我的 AI，分别用了两种问法：  
> 第一种"帮我写测试" → 输出泛泛，没覆盖 null。  
> 第二种套上 STAR 的 Action 层（指定用 BigDecimal、Mockito、JUnit 5、覆盖正常/异常/边界）→ 输出直接全面了很多。  
> 差异不在模型，在约束。

> 昨天有个线上 NPE，堆栈指向 OrderService.line58。我按 STAR 把堆栈 + 业务上下文贴给 AI，不啰嗦背景只写关键事实——第一轮分析就猜对了是 user 为 null，还给出了临时补丁和长期方案。
