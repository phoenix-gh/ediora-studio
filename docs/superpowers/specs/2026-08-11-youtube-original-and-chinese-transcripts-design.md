# YouTube 原文与中文逐字稿设计

## 目标

YouTube 视频在采集逐字稿时，以视频原语言字幕为主版本；如果 YouTube 同时提供中文字幕，则一并采集并保存。用户查看逐字稿时默认看到原文，可在原文和中文之间切换。长内容必须在弹窗内独立滚动，不能撑出容器。

## 数据与采集

- 根据 yt-dlp 元数据中的 `language` 或 `original_language` 判断视频原语言。
- 优先选择该语言的人工字幕，其次选择该语言的自动字幕；找不到原语言字幕时，使用现有音频转写作为原文版本。
- 中文版本独立选择，优先人工中文字幕，其次自动中文字幕。
- 原文与中文使用同一种版本结构：`source`、`language`、`text`、`segments` 和 `content_hash`。
- 当原语言本身是中文时，只保存原文版本，不重复生成中文版本。
- 数据库增加可空的中文逐字稿字段，已有逐字稿字段继续代表原文，兼容已有数据。
- 采集结果写入原文字段；存在独立中文字幕时，同时写入中文字段。中文采集失败不能使已成功的原文采集失败。

## 下游语义

- 内容分析、响应项交接和其他已有下游流程继续只使用原文 `transcript_text`。
- 中文版本只用于用户查看，不替换分析原稿，也不触发 AI 翻译。
- 旧数据保持可读；旧记录只有原文版本，重新提取后才可能补充中文版本。

## API

现有 `GET /youtube/videos/{video_id}/transcript` 保留原文字段，并增加可空的 `chinese` 版本对象。前端不额外请求第二个接口，打开弹窗时一次取得所有已保存版本。

## 查看交互

- 弹窗默认选择“原文”。
- 仅当存在独立中文字幕时显示“原文 / 中文”切换。
- 语言、来源、时间戳分段、纯文本回退和复制全文均跟随当前版本。
- 切换版本不重新请求后端，也不改变视频列表筛选和滚动位置。
- 内容区使用有界高度和 `overflow-y-auto`，标题、版本切换和底部复制按钮固定，只有逐字稿正文滚动。

## 错误与兼容

- 原文不存在时沿用当前失败状态和重试流程。
- 中文不存在时不显示切换，不视为错误。
- 时间戳链接仍限制为可信 YouTube 域名。
- API 缺少新增字段时，前端按“仅原文”处理。

## 验证

- 后端测试覆盖原语言优先级、原文与中文同时采集、原语言为中文、中文失败不影响原文、API 兼容。
- 前端测试覆盖默认原文、版本切换、复制当前版本、无中文时隐藏切换以及滚动容器样式。
- 运行 YouTube 相关聚焦后端和前端测试，并执行相关 ESLint 检查。
