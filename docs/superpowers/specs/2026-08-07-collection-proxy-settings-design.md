# 采集网络代理设置设计

## 目标

在 Ediora 设置页提供一个采集代理地址。保存后，后端将该地址同时设置为运行进程的 `HTTP_PROXY` 与 `HTTPS_PROXY`，供以下采集链路使用：

- feedgrab / X
- Reddit
- YouTube
- GitHub
- 论文采集

配置应持久化、保存后立即生效，并在服务重启后自动恢复。空地址表示关闭代理。

## 非目标

- 不修改 `backend/.env`。
- 不为每个来源提供独立代理。
- 不增加代理池、自动切换、健康检查或连通性测试。
- 不把代理配置传给独立的 Node 创作 Worker。
- 不承诺隔离同一 Python 后端进程中的其他环境变量感知型网络请求；`HTTP_PROXY` 和 `HTTPS_PROXY` 本身是进程级设置。

## 方案选择

采用“数据库持久化 + 运行时同步环境变量”方案：

1. 设置页只接收一个代理 URL。
2. 配置保存到现有 `app_settings` 键值表。
3. 保存成功后，后端立即将同一个 URL 写入 `os.environ["HTTP_PROXY"]` 和 `os.environ["HTTPS_PROXY"]`。
4. 后端启动时从数据库读取配置并再次同步环境变量。
5. 清空配置时删除这两个运行时环境变量。

该方案与 feedgrab 当前的代理读取方式一致，也能让继承环境变量的 YouTube 子进程以及默认信任系统环境的 HTTP 客户端直接使用代理。

## 配置模型与验证

新增应用配置键 `collection_proxy_url`，默认值为空字符串。

设置 API：

- `GET /api/settings` 返回代理是否启用及可安全展示的值。
- `PUT /api/settings` 接受 `collection_proxy_url`。
- 输入在保存前去除首尾空白。
- 空字符串合法，表示关闭。
- 非空地址只允许 `http://`、`https://` 或 `socks5://`，且必须包含主机。
- 非法配置返回 422，不更新数据库，也不改变当前环境变量。

代理 URL 可能包含用户名和密码。API 不应把已保存的认证信息原样返回浏览器：

- 无认证信息的 URL 可以完整返回，方便编辑。
- 含认证信息时只返回脱敏预览，并通过 `collection_proxy_url_set` 表示已经配置。
- 浏览器在已配置且输入框留空时保持原值；用户通过单独的“清除代理”操作关闭配置。

## 运行时同步

增加一个边界清晰的后端辅助模块，负责：

- 验证和标准化代理 URL。
- 将代理地址同步到 `HTTP_PROXY`、`HTTPS_PROXY`。
- 清除由应用管理的代理变量。

为避免删除运维人员在启动服务前显式提供的环境变量，模块在首次接管时记录原始值：

- 数据库未配置代理时，不覆盖启动环境已有的 `HTTP_PROXY`、`HTTPS_PROXY`。
- 用户在设置页保存代理后，应用接管这两个变量。
- 用户随后清除设置时，恢复服务启动时的原始值，而不是无条件删除。

启动顺序：数据库初始化完成后、定时采集任务注册前读取 `collection_proxy_url` 并同步。这样首轮定时采集也会使用正确代理。

保存顺序：先验证，再持久化，数据库保存成功后同步运行时环境。若持久化失败，现有运行时代理保持不变。

## 设置页面

在“设置 → 数据采集”增加“采集网络代理”表单区：

- 一个“代理地址”输入框。
- 示例占位符：`http://127.0.0.1:7890`。
- 说明同一地址会写入 `HTTP_PROXY` 和 `HTTPS_PROXY`。
- 明确列出适用来源：X/feedgrab、Reddit、YouTube、GitHub、论文。
- 显示“已启用”或“未启用”。
- 提供“保存”和“清除代理”操作。
- 保存成功提示“采集代理已保存并立即生效”，无需重启服务。

表单沿用现有主题变量和通用 Input/Button/FormSection 组件，适配浅色与深色主题。

## 错误处理与日志

- URL 格式错误由设置接口返回明确的中文错误，前端展示具体原因。
- 运行时同步只处理进程内字典操作，不执行网络请求。
- 日志只记录代理已启用、已关闭及协议，不记录完整 URL、用户名或密码。
- 各采集器现有的网络错误处理保持不变；代理失败会继续出现在对应采集日志中。

## 测试

后端测试覆盖：

- 合法的 HTTP、HTTPS、SOCKS5 地址。
- 非法协议、缺失主机和空值。
- 设置保存后两个环境变量立即更新。
- 清除设置后恢复启动时原有环境变量。
- 服务启动恢复数据库代理，并发生在任务注册前。
- 含认证信息的代理不会通过设置 API 明文返回。
- 保存失败时不改变当前运行时环境。

前端测试覆盖：

- 数据采集页面展示代理表单和适用来源。
- 一个输入值保存为 `collection_proxy_url`。
- 已配置凭据代理时显示脱敏状态，空输入不会覆盖原值。
- 清除操作显式提交空值。
- API 错误信息可见，保存成功后更新页面状态。

## 验收标准

- 用户只填写一次代理地址。
- 保存后无需重启，后续采集使用该代理。
- 重启后配置仍生效。
- 清除后停止使用应用设置的代理，并正确恢复启动环境。
- 设置接口、页面和日志均不泄露代理认证信息。
