# 提示词优先的每日 Agent 任务设计

日期：2026-08-09

## 目标

把当前“每日创作规则”改造成通用的定时 Agent 任务。每条任务由两部分组成：

1. 调度信息：任务名称、执行方式、日期、时间、时区、启停状态。
2. Agent 提示词：本次任务实际执行的完整自然语言指令。

提示词是唯一的业务执行依据。素材目录、内容类型、目标数量、去重天数、内容去向和附加要求等结构化选项不再驱动后台固定流程，只用于在界面上快速生成一段可编辑提示词。

## 核心原则

- 调度器只决定何时执行，不解释提示词中的业务含义。
- Agent 收到规则运行快照中的完整提示词，并自主选择启用的 Skill、工具和执行步骤。
- 框架不再要求特定业务工具，也不根据固定内容类型判断任务是否完成。
- `save_daily_creation_outputs` 从 MCP 工具、Agent 提示词、完成证据和测试契约中移除。
- 通用草稿保存继续使用 `save_draft`；提示词需要保存 X 草稿时，应明确给出 `draft_type="x"` 等合法参数。
- 已有运行记录和历史批次数据保留，只停止产生新的专用批次，不删除历史数据。

## 数据模型

### 规则

`DailyCreationRule` 增加非空的 `prompt` 字段，作为执行时读取的唯一业务指令。

现有调度字段继续保留：

- `name`
- `execution_mode`
- `scheduled_date`
- `scheduled_time`
- `timezone`
- `enabled`
- `deleted_at`

现有的素材目录、目标数量、去重天数、内容类型、内容去向和附加要求字段在第一阶段保留，用作快速生成面板的可恢复状态和旧数据迁移来源。后台执行器不得再读取这些字段拼接或改变任务目标。

### 运行快照

创建运行记录时，把当时的完整 `prompt` 写入 `rule_snapshot`。规则之后被修改，不影响已创建或正在执行的运行。

旧规则首次读取或迁移时，按照现有字段生成等价提示词，并写入 `prompt`。迁移后的执行只读取 `prompt`，避免同时存在两套业务规则来源。

### 历史数据

`daily_creation_output_batches` 和已有 `ContentUsageLedger` 数据暂时保留，用于历史日志和既有草稿追溯。新任务不再创建 `DailyCreationOutputBatch`。删除历史表和数据属于独立的数据清理任务，不包含在本次改造中。

## 界面设计

任务编辑对话框分为三个区域：

1. 基本信息：名称、执行方式、日期、时间、时区和启停状态。
2. Agent 提示词：始终可见的多行文本编辑器，是保存和执行的最终内容。
3. 快速生成提示词：保留当前选择面板，作为可展开的辅助区域。

快速生成面板继续提供当前常用选项，例如素材目录、内容类型、数量、去重天数、账号、内容去向和附加要求。点击“生成提示词”后，把选项转换成完整、明确的自然语言指令并填入提示词编辑器。

生成提示词不会在用户修改选项时自动覆盖编辑器。提示词已有人工修改时，再次生成必须通过明确按钮触发；界面应提示此次操作会替换当前文本。

任务列表优先展示提示词摘要、执行时间、上次运行、下次运行和最近状态，不再把“目标数量”和“已创建数量”当作所有任务都具备的通用指标。

## 提示词生成规则

快速生成器输出完整、自包含的提示词，至少包含：

- 任务目标和期望产物。
- 可使用的素材目录或其他数据范围。
- 数量、格式、长度、内容风格等要求。
- 去重要求及需要调用的只读工具。
- 保存位置与保存工具的合法参数值。
- 用户填写的附加要求。

生成器需要写出工具参数的精确合法值。例如 X 草稿使用 `save_draft` 时明确要求 `draft_type="x"`，不能让 Agent 自行发明枚举值。

生成后的文本只是普通提示词。用户可以删除、扩写或完全替换，不保留隐藏的结构化业务约束。

## Agent 执行

每日任务继续使用独立的任务流标识，便于任务看板过滤和历史查询，但执行器改为通用提示词 Agent：

1. 读取运行快照中的 `prompt`。
2. 创建持久化 `AgentExecution`。
3. 向 Agent 提供启用的 Skill 目录和全局工具。
4. Agent 根据提示词自主决定是否加载 Skill、读取哪些资料以及调用哪些工具。
5. 持久化完整模型消息、Skill 激活记录和工具调用审计。
6. Agent 正常结束且没有未处理的模型或工具错误时，任务成功；运行失败时保留可重试的任务状态和完整错误日志。

执行器不再注入 X 短帖、固定数量、固定目录、严格去重或专用保存工具等业务指令，也不再要求 `save_daily_creation_outputs` 作为完成证据。

框架只负责通用安全边界、工具参数校验、幂等调用审计和任务生命周期。是否必须保存草稿、生成图片或写入资产库，由提示词表达并由 Agent 完成。

## `save_daily_creation_outputs` 移除范围

本次移除包括：

- MCP 工具注册和工具说明。
- 每日 Agent 目标中的调用要求。
- `requiredTools` 和专用完成证据解析。
- Agent 运行类型中的专用完成结果。
- 新运行对 `persist_daily_creation_output_batch` 的依赖。
- 对应的前后端单元测试和集成测试契约。

保留范围：

- 已存在的数据库表和历史批次记录。
- 为历史页面读取旧运行详情所需的兼容读取代码。

## 错误处理

- 新建或更新任务时拒绝空提示词。
- 创建运行时必须保存提示词快照；缺失快照的运行不得启动。
- Agent 模型调用失败、工具调用失败或执行步数耗尽时，任务按现有可重试机制标记失败。
- 快速生成器不能生成提示词时，保留用户已经输入的文本并显示错误，不清空编辑器。
- 旧规则迁移失败时保持停用并显示原因，不使用空提示词执行。

## 测试范围

### 后端

- 规则 API 可以创建、更新和读取 `prompt`，并拒绝空值。
- 旧规则可生成并持久化等价提示词。
- 调度创建的运行快照包含当时的完整提示词。
- 执行器只读取快照提示词，不再读取结构化业务字段。
- MCP 工具列表不再包含 `save_daily_creation_outputs`。
- 历史批次仍可被任务日志读取。

### Agent 运行时

- 每日任务不再声明 `save_daily_creation_outputs` 为必需工具。
- 自然语言提示词原样进入模型请求。
- Agent 可以根据提示词调用 `save_draft`、资产或图片工具。
- Skill 目录仍然提供给 Agent，并记录实际激活结果。
- 工具失败会使任务失败，成功执行不会要求某个特定业务工具。

### 前端

- 提示词编辑器是必填项和最终提交值。
- 快速生成面板可以生成完整提示词。
- 用户可以在生成后继续编辑。
- 修改快速选项不会自动覆盖人工编辑文本。
- 再次生成会明确提示替换行为。
- 任务列表展示提示词摘要和通用执行状态。

## 验收标准

- 新建每日任务时，可以只填写调度信息和一段自由提示词。
- 当前选择面板可以生成提示词，生成结果可编辑后再保存。
- 同一份提示词原样保存在运行快照和 Agent 日志中。
- 新运行的 Agent 工具目录中不存在 `save_daily_creation_outputs`。
- 每日任务不再因缺少该工具或专用完成证据而失败。
- 需要保存 X 草稿的生成提示词明确使用 `save_draft` 和 `draft_type="x"`。
- Job #1219 的“双保存路径”在新执行器中不再存在：框架不会再追加第二套专用批次保存。
