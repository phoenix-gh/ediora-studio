# X 订阅独立采集频率设计

## 目标

让每个 X 订阅拥有独立的自动采集间隔，避免所有订阅被同一个全局频率绑定。

## 设计决定

- `XSubscription` 增加 `collect_interval_minutes`，范围为 5–1440 分钟，默认 15 分钟。
- 现有全局 `x_collect_interval_minutes` 保留，改为新订阅默认频率；已有订阅迁移时使用当前全局值，无法读取时使用 15 分钟。
- X 订阅管理中的“更多操作”增加“设置采集频率”对话框，提供 5、10、15、30、60、180、360、720、1440 分钟选项。
- 调度器每分钟检查一次启用订阅，依据每个订阅的 `last_collected_at` 和独立间隔判断是否到期；手动采集不受频率限制，但成功后会刷新 `last_collected_at`。
- 时间线订阅和搜索订阅使用相同的频率逻辑；停用订阅不采集。
- AI 情报分析和主题素材筛选继续跟随采集产生的新帖，不增加第二套频率配置。

## 数据流

```text
XSubscription.collect_interval_minutes
       -> 每分钟调度检查
       -> last_collected_at + interval 是否到期
       -> _collect_one
       -> 新帖入库 / 情报分析 / 主题素材筛选
```

## 迁移

- 新数据库由 ORM 创建字段。
- 旧数据库通过 `_add_columns` 增加 `INTEGER NOT NULL DEFAULT 15`。
- 仅在首次增加字段时，从 `app_settings.x_collect_interval_minutes` 读取并填充已有订阅，值限制在 5–1440；后续启动不覆盖用户已设置的订阅值。

## 界面与接口

- `SubscriptionOut` 返回 `collect_interval_minutes`。
- 创建接口允许显式传入间隔；未传入时读取全局默认。
- Patch 接口允许修改间隔并做 5–1440 校验。
- 订阅行展示“每 N 分钟”，设置对话框保存后刷新订阅列表。
- 设置页保留全局字段，但文案改为“新订阅默认采集间隔”。

## 验收标准

1. 每个订阅可独立保存并返回采集间隔。
2. 一个订阅到期时不会强制采集其他未到期订阅。
3. 首次启动和旧数据库迁移不会丢失已有全局频率配置。
4. 手动采集不被自动频率拦截，成功采集后下一次自动采集按新时间计算。
5. 搜索和时间线订阅都遵循独立频率。
6. 情报分析和主题素材入库仍只由新帖派发，不重复派发。
