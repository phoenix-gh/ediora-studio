# X 主题素材筛选补充要求设计

## 目标

允许用户在每条 X 主题素材入库规则中填写一段“AI 筛选要求”，补充目标目录和关键词之外的内容判断标准，让 `topic_source` Agent 更准确地决定帖子是否进入创作资产目录。

## 设计决定

- 在 `TopicSourceRule` 上增加 `screening_prompt` 字段，空字符串表示不配置额外要求。
- 配置入口继续使用现有“配置素材入库”对话框，不新增页面或抽屉。
- 额外要求只补充“是否适合入库”的判断，不改变目标目录、关键词初筛、去重和入库流程。
- Worker 继续使用固定的 `accepted_tweet_ids` JSON 输出契约；用户填写的文字不能改变输出格式，也不能要求 Agent 执行其他工具或业务流程。
- AI 输入同时包含目标目录、关键词、额外要求和候选帖子原文。关键词仍由后端先做确定性的候选过滤。
- 已保存的规则更新后，只影响后续尚未产生 `TopicSourceDecision` 的候选帖子；已经接受或拒绝的帖子不因修改要求而自动重审。
- 数据库升级通过现有 `_add_columns` 机制添加非空文本列，历史规则默认空字符串。

## 数据流

```text
配置对话框
  -> TopicSourceRule(directory, keywords, screening_prompt)
  -> 候选接口（关键词确定性初筛）
  -> topic_source Worker（目录 + 关键词 + 补充要求 + 原文）
  -> accepted_tweet_ids
  -> 去重
  -> CreativeAsset 或 TopicSourceDecision(accepted=false)
```

## 提示词边界

Worker 使用固定系统指令说明角色、宁缺毋滥和 JSON 返回格式；补充要求以明确的“用户配置的筛选要求”区块传入。固定输出契约放在动态要求之后再次强调，避免配置内容覆盖协议。例如用户可以写“只接受有具体案例和方法的帖子”，但不能通过该字段改变为输出标题、调用工具或绕过去重。

## 界面

- 在关键词输入下方增加多行文本框，标题为“AI 筛选要求”。
- 占位提示给出具体示例，如“只保留有具体案例、数据或可执行方法的内容；纯广告不要入库”。
- 保存时去除首尾空白；空值正常保存，不阻止规则使用。
- 对话框仍显示现有规则的目录、关键词和补充要求，编辑时可继续修改。

## 验收标准

1. 新建和编辑主题素材规则都能保存、返回并再次加载 `screening_prompt`。
2. 旧数据库升级后已有规则的 `screening_prompt` 为 `""`，应用正常启动。
3. Worker 的模型请求包含目录、关键词和配置的补充要求。
4. Worker 仍只接受合法的 `accepted_tweet_ids` JSON，补充要求不能改变解析契约。
5. 未配置补充要求时，现有筛选行为保持不变。
6. 接受、拒绝、去重和决策持久化逻辑保持不变。
7. 前端相关测试和后端资产路由测试通过。

## 不在本次范围

- 不增加评分、拒绝理由、标题、标签或多级内容分类。
- 不自动重审已经产生决策的帖子。
- 不改变“情报分析”开关和情报站流程。
