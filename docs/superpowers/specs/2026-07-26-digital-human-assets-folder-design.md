# 数字人资产系统文件夹

## 目标

在“创作资产 → 多媒体”目录树中增加一个系统级文件夹“数字人资产”，集中展示所有实际
用于数字人口播流程或由该流程生成的多媒体资产。

该文件夹由系统维护，不按数字人角色拆分，用户不能重命名或删除。已有数字人资产和后续
新增资产都应自动归档，无需用户手动整理。

## 已确认的产品边界

- 只增加一个顶级文件夹“数字人资产”，不为每个数字人建立子文件夹。
- 文件夹属于多媒体资产树，不增加新的顶级资产类型或独立页面。
- 文件夹不可重命名、不可删除；前后端都必须执行该约束。
- 人物形象、声音样本、默认环境图、项目覆盖环境图和成功生成的口播成片都归入该文件夹。
- 系统启动时补齐文件夹，并归档现有数字人的关联素材和历史成片。
- 本次只保护系统文件夹，文件夹内资产沿用现有删除规则。
- 文章资产、普通多媒体目录及数字人口播页面的现有交互保持不变。

## 方案选择

采用带稳定系统标识的兼容方案：

- `CreativeAssetDirectory` 增加可空的 `system_key`。
- “数字人资产”使用固定 `system_key=digital_human_assets`。
- 目录显示名仍为“数字人资产”，资产继续使用现有 `CreativeAsset.directory` 字符串归档。
- 因为系统目录不能改名，现有按目录名称过滤资产的方式仍然稳定。

不采用只按中文名称判断的方案，因为名称不应承担权限语义；也不在本次把全部资产迁移为
目录 ID 外键，因为这会扩大迁移和前端改造范围。

## 数据模型和迁移

### CreativeAssetDirectory

新增字段：

| 字段 | 说明 |
| --- | --- |
| `system_key` | 可空、唯一；普通目录为空，数字人目录为 `digital_human_assets` |

目录 API 响应增加：

| 字段 | 说明 |
| --- | --- |
| `is_system` | 是否为系统目录，供前端决定锁定状态 |

数据库初始化执行幂等迁移：

1. 增加 `system_key` 字段和非空值唯一约束；
2. 按 `system_key=digital_human_assets` 查找系统目录；
3. 不存在时创建多媒体顶级目录“数字人资产”；
4. 已存在同名普通目录时，将其升级为系统目录，保留其中已有资产；
5. 执行存量数字人资产归档。

迁移不得创建重复目录，也不得覆盖文章目录中的同名文件夹。

## 归档规则

后端提供一个小型领域服务，接收资产 ID 集合，把存在的多媒体资产的
`directory` 更新为“数字人资产”。重复调用必须幂等。

以下业务节点调用该服务：

1. **创建数字人角色**
   - 人物形象；
   - 声音样本；
   - 默认环境图。
2. **编辑数字人角色**
   - 新选择的人物形象、声音样本或默认环境图。
3. **创建或编辑口播作品**
   - 项目覆盖环境图。
4. **创建成片版本**
   - 本次实际使用的默认或覆盖环境图。
5. **成片成功回存**
   - `TalkingVideoRender.video_asset_id` 指向的本地 MP4。

选择一个原本位于普通目录的素材用于数字人口播后，该素材移动到“数字人资产”。空选、
取消选择或尚未保存的候选素材不会归档。

### 存量归档

启动迁移收集以下资产 ID 并归档：

- 所有 `DigitalHuman` 的人物形象、声音样本和默认环境图；
- 所有 `TalkingVideoProject` 的非空覆盖环境图；
- 所有 `TalkingVideoRender` 的环境图和非空本地成片资产。

归档只更新数据库目录字段，不移动 `backend/uploads` 中的物理文件，也不重新上传 HeyGen。

## API 行为

### 目录列表

`GET /api/assets/directories?asset_type=media` 返回“数字人资产”，并标记
`is_system=true`。

### 重命名和删除

以下请求命中系统目录时返回 `409`：

```text
PATCH  /api/assets/directories/{id}
DELETE /api/assets/directories/{id}
```

错误文案分别为：

- `系统目录不能重命名`
- `系统目录不能删除`

约束由后端执行，不能只依赖隐藏前端按钮。

普通目录的创建、重命名、递归删除和资产移回未分类行为保持不变。

## 前端交互

“创作资产 → 多媒体”的目录树中：

- “数字人资产”与其他顶级目录一起显示；
- 名称前显示锁图标；
- 悬停时不显示编辑和删除按钮；
- 仍可点击查看，并继续使用图片、视频、音频筛选；
- 目录数量按当前已有逻辑统计。

不增加右侧预览栏；多媒体仍使用紧凑网格和双击弹窗预览。

## 错误处理

- 系统目录创建和存量归档必须幂等，重复启动不能报冲突。
- 归档时忽略已删除或非多媒体资产，不阻塞数字人主流程。
- 创建或更新数字人的事务中，如果有效素材归档失败，事务整体回滚，避免角色已保存但
  资产分类未同步。
- 成片回存后的归档失败沿用 durable job 的失败与重试机制，不重复创建 HeyGen 视频。
- 直接调用目录删除或改名 API 时返回明确的 `409`，不修改任何资产。

## 测试

### 后端

- 初始化会创建唯一的“数字人资产”系统目录。
- 同名普通多媒体目录会被升级，不会重复创建。
- 重复初始化和重复归档保持幂等。
- 创建、编辑数字人会归档人物图、声音和默认环境图。
- 创建或编辑口播作品会归档覆盖环境图。
- 成片成功后会归档本地 MP4。
- 存量数字人、项目和成片资产会被补归档。
- 系统目录重命名和删除返回 `409`；普通目录行为不变。

### 前端

- 系统目录显示锁定状态。
- 系统目录不渲染编辑和删除操作。
- 普通目录仍可编辑和删除。
- 点击系统目录后仍能使用媒体类型筛选和双击预览。

### 验收

- 启动现有 Docker 服务后，多媒体目录树出现唯一的“数字人资产”。
- 当前测试数字人的人物图、声音、环境图和历史成片都出现在该文件夹。
- 新建或编辑数字人、替换环境、生成新成片后，相关资产自动进入该文件夹。
- 前端无法删除或重命名该文件夹，直接调用 API 也会被拒绝。
- 前后端完整自动化测试、生产构建和浏览器页面验收通过。
