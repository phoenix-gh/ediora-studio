# 文字视频「动感大字 V2」动效系统设计

## 背景

现有五套文字视频模板已经可以选择、预览和导出，但动效层仍主要依赖同一个
`TimedText` 组件。当前实现只有短暂的 `fade-up` 与 `scale` 入场，文字进入后
长时间静止；切换场景时新文字从透明状态开始，容易产生空白闪帧；模板清单中
声明的转场也没有真正进入渲染链路。

此外，现有渲染协议只向 Remotion 提供场景级的开始时间、结束时间、文字、
高亮词和动画名称。词级时间没有进入渲染输入，因此「字幕聚焦」无法在说到
具体词时触发，「口播律动」也只能使用模拟波形而不是真实音频数据。

本次先重做 `kinetic-punch`，建立一套可复用的时间、生命周期和转场底座。
验证完成后，其余模板再基于同一底座分别设计动作语言，而不是继续共享一套
换色后的文字动画。

## 产品目标

将「动感大字」升级为适合 AI、商业和观点口播的“信息差爆点”模板：

- AI 按语义把长段落拆成连续的 4–10 字短句，用户可以编辑；
- 短句与关键词根据词级时间精准触发；
- 每个短句具有进入、保持、强调和退出的完整生命周期；
- 相邻画面使用确定性的重叠转场，场景边界不再出现空白帧；
- AI 只生成受约束的结构化编排，不生成或修改 Remotion 代码；
- 旧项目不需要迁移，也能继续预览和导出。

本期不同时重做其余四个模板，不提供自由关键帧、多轨时间线或任意动画代码。

## 已选方案

采用“共享动效底座 + 动感大字 V2”的方案。

不选择只调整现有 `TimedText` 参数，因为它不能解决词级同步、退出动画、
重叠转场和模板同质化。不在本期建立任意关键帧 DSL，因为它会扩大 AI 输出
的校验面和编辑器复杂度。

Remotion 仍然只有一个工程。每个模板是一个版本化 Composition，每个视频
项目只是保存渲染数据，不复制 Remotion 项目。

## 数据流

完整链路为：

```text
已确认的完整音频
  → Whisper 词级时间
  → AI 语义拆句、重点识别和动作建议
  → 用户编辑
  → 规范化与校验
  → Remotion 确定性渲染
```

AI 不可用或返回非法结构时，使用标点、文字长度和词时间进行规则拆分。规则
方案必须能够独立完成预览和导出，不依赖再次调用 AI。

## 渲染协议

保留现有 `audio + segments + templateProps` 顶层结构，为场景增加可选的
`chunks`。时间统一使用完整音频上的绝对秒数。

```ts
type KineticWordCue = {
  text: string
  start: number
  end: number
  emphasis: 'normal' | 'highlight'
}

type KineticChunk = {
  id: string
  start: number
  end: number
  text: string
  motionPreset: 'impact' | 'reveal' | 'contrast'
  emphasis: 'normal' | 'punch'
  words: KineticWordCue[]
}

type KineticSegment = {
  id: string
  start: number
  end: number
  text: string
  animation: string
  highlight: string[]
  transition?: 'block-wipe'
  intensity?: number
  chunks?: KineticChunk[]
}
```

`chunks` 是 Remotion 可直接消费的最终编排，不要求渲染器再次理解自然语言。
每个 `words` 项保存对应口播词的时间，`emphasis` 决定在该时间点是否触发
关键词动作。

渲染协议不是编辑器的唯一数据源。项目仍以 `scene_plan` 为可编辑真相源，
在每个现有 scene 上增加可选的 motion document：

```ts
type KineticChunkPlan = {
  id: string
  fromWordId: string
  throughWordId: string
  displayText: string
  highlight: string[]
  motionPreset: 'impact' | 'reveal' | 'contrast'
  emphasis: 'normal' | 'punch'
}

type KineticSceneMotionPlan = {
  transition: 'block-wipe'
  intensity: number
  chunks: KineticChunkPlan[]
}
```

保存时使用稳定的 word ID，避免重新对齐音频后残留脆弱的浮点时间。启动预览
或导出前，现有 scene-plan 投影层再把 word ID 转成 render input 中的绝对
秒数和 `words`。`render_input` 是可复现的渲染快照，不反向覆盖 scene plan。

协议校验规则：

- segment 和 chunk 按时间升序排列，不允许越过父级范围；
- chunk 不允许相互重叠或产生未解释的时间空洞；
- word cue 必须位于所属 chunk 内并保持顺序；
- chunk 文字按规范化空白和标点拼接后必须完整覆盖当前 scene 的
  `displayText`，本次动效 AI 不允许擅自遗漏或改写；
- `intensity` 限制在 `0–1`；
- 不支持的动作降级为 `reveal`，不支持的转场降级为安全的块状切换；
- 校验失败时保留上一次有效编排，不覆盖项目状态。

旧项目没有 motion document 时，投影层将每个旧 scene 转成一个 `reveal`
chunk。它使用 scene 的词范围、起止时间和现有高亮信息，不调用 AI，也不
修改数据库中的原始项目；只有用户主动执行“AI 优化动效”或“自动拆句”后
才保存新版编排。

## 共享动效底座

公共层负责时间与安全约束，不负责定义各模板的视觉风格：

- 把秒数稳定换算为 Remotion 帧；
- 提供 `enter → hold → emphasize → exit` 生命周期进度；
- 在场景边界同时保留出场层和下一场景的背景入场层；
- 统一处理首帧、末帧、极短 chunk 和缺失词时间；
- 保证 Player、单帧渲染和最终 MP4 使用相同计算；
- 禁止依赖随机数或浏览器实时状态。

共享层不再输出一套固定的文字 JSX。`kinetic-punch-v2` 拥有自己的排版、色块、
遮罩和关键词组件；其他模板以后只复用时间与转场能力。

## 动感大字 V2 动作语言

视觉方向是专业、利落的“信息差爆点”，不使用持续抖动、随机故障或无语义的
旋转。

### 短句生命周期

1. **进入，6–10 帧**：强调色块先覆盖安全区域，文字通过遮罩快速揭示。
2. **保持**：根据 chunk 时长做轻微的镜头推进或排版位移，避免长时间完全
   静止。
3. **强调，8–14 帧**：播放到对应 word cue 时，关键词执行一次
   `放大 → 反色或变色 → 回稳`。
4. **退出，5–8 帧**：文字和色块分层退出，出场内容持续覆盖画面，直到下一
   场景的背景层已经进入。

场景转场围绕真实边界展开：下一场景的背景与色块可以提前最多 6 帧开始进入，
但下一句文字只能在对应口播时间出现。这样既消除空白帧，也不会提前泄露下一
句内容。

### 动作预设

- `impact`：关键词重击放大，用于结论、数字和反差点；
- `reveal`：短句分层遮罩揭示，用于解释和铺垫；
- `contrast`：前后半句进行黑底与亮色块反转，用于“以为……其实……”结构。

AI 可以选择预设和 `intensity`，但每种预设的关键帧、缓动和可用属性由模板
代码固定。相同输入重复渲染必须得到相同结果。

### 响应式排版

- 每个 chunk 优先显示 4–10 个汉字，最多三行；
- 重点词不能跨越低对比度区域；
- 长句拆成连续 chunk，不通过无限缩小字号塞入一屏；
- 16:9、9:16 和 1:1 共用同一语义编排，分别计算字号、断行、安全区和色块；
- 左上角品牌、Logo、强调色等沿用现有模板设置，不重新硬编码产品名称。

## AI 编排

AI 输入包含当前 scene 的 `displayText`、词级时间、模板支持的预设和用户
指令。输出只包含：

- 以 word ID 表示的 chunk 边界；
- chunk 显示文字；
- 重点词；
- `motionPreset`；
- `emphasis`；
- `intensity` 和受支持的转场。

本次“AI 优化动效”不得修改当前 scene 的 `displayText`，也不得产生自由
CSS、React、Remotion 代码或任意关键帧。用户仍可通过已有分镜文字编辑能力
主动修改显示文字；这不会修改口播或音频，但会使旧动效编排失效并要求重新
拆句。服务端和前端都使用同一套领域约束校验输出。

规则兜底按以下顺序工作：

1. 优先在标点和明显停顿处分割；
2. 结合词级时间，把单屏长度控制在 4–10 字附近；
3. 无词级时间时按字符比例分配场景时长；
4. 默认使用 `reveal`，包含数字、否定或结论词时可使用确定性的 `impact`；
5. 极短片段与相邻片段合并，避免无法完成进入和退出动画。

## 编辑器交互

在现有“成片时间轴”阶段增加“动效编排”，不新增侧边抽屉。

场景区域显示：

- 原始场景文字和音频区间；
- AI 或规则拆出的短句卡片；
- 每个短句的起止时间、动作预设、重点词和强调强度；
- 当前场景预览和整片预览入口。

提供三个操作：

- **AI 优化动效**：重新分析语义、拆句、重点和动作；
- **自动拆句**：只使用规则与词时间，不改变文字；
- **手动调整**：重新划分短句边界，并编辑重点和动作；边界吸附到相邻词
  时间点。显示文字本身继续在现有分镜编辑入口修改。

复杂参数继续使用项目 Dialog，不使用浏览器原生输入框或侧边抽屉。保存沿用
现有项目状态机制；刷新或重新进入项目后必须恢复同一编排。修改已保存的编排
会使旧成片过期，但不会重新生成或失效已确认音频。

## 错误处理

- Whisper 没有词级结果：显示“使用估算时间”，按字符比例生成 chunk；
- AI 请求失败：保留当前有效编排，并允许直接使用规则拆句；
- AI 返回非法结构：展示具体校验原因，不写入项目；
- 场景过短：合并相邻 chunk，或使用无强调的短版 `reveal`；
- 预览数据与保存数据不一致：禁止启动导出，并提示先保存最新编排；
- 旧模板版本：继续使用旧 Composition，用户主动选择 V2 后才应用新动作系统。

## 版本与发布

为了保证历史成片的视觉可复现性，新实现注册为
`kinetic-punch-v2@1`：`templateId` 为 `kinetic-punch-v2`，
`templateVersion` 为 `1`，Composition ID 为 `kinetic-punch-v2`。它不
静默改变 `kinetic-punch-v1@1` 的渲染行为。

模板选择界面可以把 V2 显示为新的默认“动感大字”；已有项目仍保存原来的
`id@version`。用户切换到 V2 时保留音频和场景文字，生成规则编排并将已有
成片标记为过期。

## 验收标准

- 所有 chunk 和 scene 边界均不存在只剩背景、文字意外消失的空白闪帧；
- 有词级时间时，关键词强调开始位置与对应口播误差不超过约 2 帧；
- 任意连续一秒都有有意义的排版推进、语义强调或场景转场；
- 长句不会缩成密集的小段落；
- 相同输入重复预览和导出得到一致画面；
- 16:9、9:16、1:1 均满足安全区和文字对比度要求；
- 旧项目无需数据迁移即可继续使用 V1 预览和导出；
- AI、Whisper 或编排校验失败时仍可通过规则方案出片；
- 预览、选帧检查和 MP4 导出使用同一份已保存数据。

## 验证方案

### 领域测试

- 规范化旧 segment 为单 chunk；
- 接受有效 chunk/word cue，拒绝越界、重叠、空洞和文字缺失；
- AI 非法动作降级，非法内容不覆盖上一次有效编排；
- 规则拆句在有词时间和无词时间两种情况下输出确定结果。

### Remotion 测试

- 为三个动作预设分别覆盖进入、强调、保持和退出关键帧；
- 渲染场景边界前后逐帧快照，确认前景覆盖连续且下一句不会提前出现；
- 三种宽高比使用相同 fixture 渲染关键帧；
- 相同 props 重复渲染得到一致快照；
- 极短、超长、无高亮和缺失词时间 fixture 均可渲染。

### 产品测试

- 编辑短句、动作和重点后保存，刷新页面状态不丢失；
- “AI 优化动效”失败时旧编排保持不变；
- 修改编排正确地使现有成片过期，但不使已确认音频失效；
- V1 历史项目继续预览，主动切换 V2 后生成兼容编排；
- 使用真实项目检查关键帧，并导出包含 H.264 视频和 AAC 音频的 MP4。

## 后续扩展

动感大字 V2 验证后，再按模板逐个扩展：

- `caption-focus` 接入真实词级聚焦；
- `voice-pulse` 使用真实音频频谱，不再使用正弦模拟；
- `editorial-card` 增加卡片级进入、保持与退出；
- `tech-text` 建立真正的 soft-push 场景转场。

这些模板共享时间和生命周期底座，但不共享动感大字的视觉组件。
