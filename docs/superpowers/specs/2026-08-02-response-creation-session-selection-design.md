# 待响应创作会话与列表选择解耦设计

## 背景

用户在“待响应”中点击“采纳创作”后，当前条目从“待处理”筛选结果中消失。现有列表刷新逻辑会立即选择剩余列表的第一条，而创作面板仍绑定刚采纳的条目。出于防止错条目创作的安全校验，面板随后被整体禁用，看起来像操作面板死掉。

## 目标

- 打开创作面板后，将其视为绑定当前响应条目的独立创作会话。
- 列表刷新、筛选或搜索结果变化时，不切换正在创作的条目。
- 取消创作或创建任务成功后，再把选择同步到最新列表中的下一条。
- 保留现有响应 ID、分析运行 ID 和防重复提交校验，不能把创作任务提交到错误条目。

## 非目标

- 不修改待响应的业务状态模型和后端 API。
- 不改变“采纳创作”“稍后处理”“不值得”的含义。
- 不新增跨页面持久化的创作会话。

## 交互规则

1. 点击“采纳创作”并成功获取更新后的详情后，打开绑定该响应的创作会话。
2. 随后的待处理列表刷新可以更新条目和总数，但只要创作会话仍打开，就保留当前响应 ID，不自动选择新条目。
3. 详情区继续通过已加载详情展示被采纳条目，创作类型、账号和“创建任务”保持可操作。
4. 用户点击“取消”时关闭会话；若当前响应已不在最新列表中，选择列表第一条，否则保留当前选择。
5. 创作任务创建成功时执行同样的会话关闭与选择协调。创建失败时保留会话和当前选择，便于重试。
6. 列表为空时，关闭会话后清空选择并显示空态。

## 状态设计

`creationDetail` 继续作为创作会话绑定条目的快照。新增最新列表引用，用于异步刷新后在会话结束时协调选择。

- `loadList`：先同步最新列表引用与 React 状态；如果当前创作会话绑定当前选择，则跳过自动改选，否则沿用现有“保留仍存在的选择或选择第一条”逻辑。
- `closeCreationSession`：清理会话状态后，根据最新列表协调选择。当前 ID 已不在列表时选择第一条；仍在列表时不变。
- `submitOutputs`：保留现有完整身份校验；成功后关闭会话，失败不关闭。

这样既不会因列表刷新让面板失效，也不会削弱错条目提交防护。

## 测试与验收

- 将现有“刷新后面板被禁用”的回归测试改为：采纳后列表只剩第二条，创作面板仍绑定第一条且可创建；创建 API 收到第一条 ID；成功后切换到第二条。
- 新增取消路径测试：采纳后列表排除第一条，点击取消后选择第二条且不创建任务。
- 保留重复点击、旧请求完成、详情刷新失败和详情竞态测试。
- 运行响应组件测试、相关静态检查和前端全量测试。
- 在开发环境中验证真实交互；只执行可恢复的状态变更，不实际创建创作任务，并在验证后恢复条目状态。
