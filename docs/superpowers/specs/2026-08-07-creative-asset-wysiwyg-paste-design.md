# 创作资产所见即所得编辑与网络图片本地化设计

## 背景与目标

创作资产中的文章目前复用 Markdown 源码编辑器，并固定为纯编辑模式。用户无法在
编辑过程中直接看到标题、列表、链接和图片的最终效果。现有粘贴处理只能上传剪贴板
中真实存在的图片文件；从网页复制整段图文时，HTML 中的外链图片不会保存到系统。

本次将创作资产文章编辑器改为单栏所见即所得编辑，底层仍保存标准 Markdown。同时
支持粘贴单张图片、图片 URL 和整段网页图文，并自动把其中的网络图片下载到系统。

## 范围与边界

- 只替换创作资产文章编辑器，不改变草稿箱编辑器。
- 资产保存接口和文章正文的 Markdown 存储格式保持不变。
- 支持标题、段落、粗体、斜体、删除线、链接、列表、引用、代码块、分隔线、表格和
  图片等常用结构。
- 不保留网页 CSS、字体、颜色、浮动布局、脚本、广告容器和交互组件。
- 不把资产存储格式改为 HTML，也不引入多人协作、修订历史或媒体管理后台。

## 编辑器方案

采用 Markdown 原生的 ProseMirror 系可视化编辑器，优先选择 Milkdown。编辑器内部
维护结构化文档，但对外只接收和输出 Markdown，避免使用通用富文本编辑器后再进行
HTML 与 Markdown 的双向有损转换。

新增创作资产专用的可视化编辑器组件。它负责：

1. 将已有 Markdown 渲染为可编辑的结构化内容；
2. 在内容变化时输出 Markdown 给现有资产工作区状态；
3. 接管粘贴事件并执行网页内容清洗、结构转换和图片本地化；
4. 展示图片处理状态、失败提示和重试入口；
5. 保持现有保存、切换文章和未保存变更判断的行为。

组件按编辑器边界动态加载，避免把较大的编辑器依赖加入资产列表首屏的关键包。主题
样式使用项目现有颜色变量，必须同时适配浅色和深色模式。

## 粘贴处理流程

编辑器按以下优先级处理剪贴板内容：

1. 剪贴板包含图片文件时，立即插入上传占位符并上传文件；
2. 剪贴板包含 HTML 时，先清洗危险和无关节点，再把支持的结构转换为编辑器文档；
3. 从清洗后的 HTML 收集所有 `img` 地址，先插入带原地址的图片节点，再异步批量
   请求后端进行本地化；
4. 剪贴板只有纯文本且内容是图片 URL 时，按网络图片处理；
5. 其他纯文本按普通文本或 Markdown 粘贴。

粘贴整段图文不会等待所有图片下载完成。正文结构立即进入编辑器，每张图片独立更新：

- 处理中：图片节点显示半透明遮罩和“正在保存图片”；
- 成功：节点地址替换为系统本地 URL；
- 失败：保留原外链地址，显示“本地化失败”和重试操作；
- 重试成功后再替换为本地 URL。

图片失败不阻止资产保存，也不回滚已经粘贴的正文。保存时若仍有处理失败的外链图片，
页面给出非阻塞提示；处理中的图片允许继续后台完成，完成后更新当前编辑内容并恢复
未保存状态，避免本地地址未写入资产。

## 网络图片导入接口

后端在创作资产路由下增加批量网络图片导入接口。请求包含图片 URL 列表，响应逐项
返回成功的本地 URL 或失败原因。单张失败不使整个批次失败。

服务端下载必须实施以下限制：

- 只接受 `http` 和 `https`，拒绝带用户名密码的 URL；
- DNS 解析后拒绝环回、私网、链路本地、保留地址和其他非公网地址；
- 每次重定向都重新校验协议、主机和解析地址，并限制重定向次数；
- 使用独立直连 HTTP 客户端，不继承采集代理环境变量；
- 设置连接、读取和总超时，并限制响应体最大字节数；
- 同时校验响应 `Content-Type` 和实际文件特征，只保存允许的图片格式；
- 使用系统生成的文件名，禁止远端文件名影响本地路径；
- 计算内容哈希，同一图片复用已存在文件，避免重复存储。

导入后的文件继续使用现有上传目录和 `/api/uploads/...` 访问方式，不新增独立媒体存储。
服务端错误只返回适合展示的分类信息，不暴露内部路径或网络细节。

## 状态一致性

图片上传和网络导入任务使用编辑器内唯一节点标识，而不是依赖光标位置。异步完成时
只更新对应节点，避免用户继续输入、撤销或移动图片后替换错误内容。

切换资产或离开页面时，仍沿用现有未保存变更保护。尚未完成的导入请求可以被取消；
已经保存到上传目录但尚未写入文章的图片视为普通未引用上传文件，本次不增加垃圾回收。

保存和重新打开资产后，以数据库中的 Markdown 为准。编辑器序列化必须保持受支持
结构稳定，不能在无实际编辑时反复改写 Markdown。

## 错误与交互

- 单张失败在图片附近展示状态，同时汇总提示“部分图片未保存到系统”。
- 失败原因归类为地址不可访问、非图片、文件过大、下载超时或安全限制，不展示堆栈。
- 重试只处理失败图片，不重新粘贴正文或重复上传成功图片。
- 编辑器初始化失败时显示明确错误和重试入口，不静默回退为可能覆盖内容的空编辑器。
- 上传或导入期间仍可编辑和保存；保存按钮不因图片失败被禁用。

## 测试与验收

前端测试覆盖：

- 已有 Markdown 能在可视化编辑器加载并稳定序列化；
- 粘贴图片文件会上传并插入本地 URL；
- 粘贴整段 HTML 会保留支持的正文结构并移除脚本和样式；
- HTML 中多张外链图片会批量本地化并准确替换各自节点；
- 单张失败保留原 URL，正文可保存，且重试只处理失败项；
- 深浅主题下编辑区、菜单、表格、代码块和状态提示可读；
- 切换资产时不会把异步结果写入另一篇文章。

后端测试覆盖：

- 正常公网图片成功保存并返回本地 URL；
- 批量请求逐项返回结果，部分失败不影响成功项；
- 拒绝私网、环回、危险重定向、非图片响应和超限文件；
- 下载客户端不读取 `HTTP_PROXY`、`HTTPS_PROXY` 等环境代理；
- 相同内容按哈希复用文件；
- 返回错误不泄露本地路径和内部异常。

验收时在创作资产页面分别粘贴单张网络图片和包含多张图片的网页正文，确认内容可视化
编辑、成功图片使用本地 URL、失败图片保留原链接且不阻止保存，并在刷新后保持一致。
