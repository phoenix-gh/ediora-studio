# 全局浮动 Chat 设计

## 状态

已确认设计，待编写实现计划。

## 目标

在网站所有页面提供一个持续存在的浮动 AI Chat 助手。用户点击右下角的助手形象后，打开一个不遮挡页面的可调整浮动面板，并在面板内完成完整 Chat 工作流：

- 多会话列表、新建、切换、重命名和删除；
- 消息流式回复、Markdown、思考状态和错误恢复；
- 技能选择、草稿上下文；
- 工具调用、工具结果和需要用户确认的工具审批；
- Agent 运行轨迹；
- 页面切换、关闭面板或切换会话时保持运行状态和消息状态。

后续会增加“与当前页面互动”的能力。本次只预留上下文扩展边界，不向模型注入页面内容，也不修改 Agent Prompt。

## 已确认的产品决策

1. 浮动助手挂在根布局，整个站点都可见，包括 /chat 页面。
2. 浮动面板与 /chat 页面共用同一批 Chat 会话。
3. 浮动面板拥有完整 Chat 能力，不是只读或简化版问答框。
4. 浮动面板使用非模态 Dialog：不显示全屏遮罩、不锁定页面滚动，打开后仍可操作当前页面。
5. 面板默认固定在右下角，支持用户调整宽度和高度；位置暂不支持拖动。
6. 调整后的面板尺寸保存在浏览器，支持恢复默认尺寸。
7. 页面切换不能导致浮动按钮、面板、会话、消息或流式回复闪烁、重置或中断。

## 当前实现背景

现有 Chat 已经具备可复用的后端和前端协议：

- web/lib/api/chat.ts 提供会话 CRUD、会话详情、技能/草稿加载和 UI Message 流消费；
- web/app/api/chat/route.ts 提供流式 Chat 请求、消息持久化、工具审批和恢复路径；
- backend/routers/chat.py 提供 ChatSession、ChatMessage 和运行状态 API；
- web/app/chat/ChatClient.tsx 目前将会话状态、流式状态、消息渲染、工具状态和页面布局集中在一个组件中；
- web/components/features/agent/AgentTrajectoryPanel.tsx 和 ChatAgentLogDialog 已提供运行轨迹展示能力。

本功能优先抽取现有逻辑，不新增另一套 Chat 协议，也不复制一份独立的 Agent 执行逻辑。

## 方案概览

采用根布局持久化的共享 Chat 工作区：

~~~text
RootLayout
  └─ ChatWorkspaceProvider
      ├─ AppShell / page children
      │   └─ /chat 页面工作区
      └─ GlobalChatWidget
          └─ 浮动 Chat 工作区
~~~

ChatWorkspaceProvider 在路由切换时保持挂载。页面工作区和浮动工作区只负责不同布局，不各自维护一套会话和流式运行状态。

## 组件边界

### ChatWorkspaceProvider

Provider 放在 web/app/layout.tsx 的持久化客户端层中，向 /chat 页面和全局浮动面板提供共享状态和动作。

Provider 负责：

- 加载并缓存会话列表；
- 维护当前会话 ID；
- 按会话缓存消息、加载状态、运行状态和错误状态；
- 创建、切换、重命名、删除会话；
- 创建本地用户消息和助手占位消息；
- 消费流式事件并按稳定消息/工具 ID 增量更新；
- 处理工具审批；
- 在会话加载时恢复 is_running 状态；
- 刷新完成后的持久化会话和会话列表；
- 缓存技能和草稿列表，避免两个工作区重复请求。

Provider 不负责具体的页面布局，也不根据 pathname 重建状态。

### ChatWorkspace

抽取一个共享的 Chat 工作区组件，至少支持两种布局：

- page：保留 /chat 的宽屏会话侧栏和完整内容区域；
- floating：使用浮动面板尺寸、折叠会话列表和紧凑工具栏。

共享工作区复用：

- 会话列表项、重命名和删除操作；
- 消息气泡、Markdown 渲染、图片结果；
- 工具调用/结果/审批展示；
- Chat 上下文选择器；
- 输入框和提交规则；
- Agent 运行轨迹入口。

页面版和浮动版只允许在布局、尺寸和导航行为上有差异，消息协议和运行状态处理必须共用。

### GlobalChatWidget

挂载在根布局，与 AppShell 同级或位于其持久化容器内：

- 默认只渲染固定尺寸的浮动助手按钮；
- 点击后打开非模态浮动面板；
- 面板关闭时不卸载 Provider，也不取消正在运行的 Chat；
- 所有页面，包括 /chat，都保留浮动入口；
- Dialog 内容通过 Portal 渲染到页面顶层，避免被页面的 overflow 或局部层叠上下文裁剪。

现有 Dialog 基于 Base UI Dialog。浮动面板使用 modal={false}，保留 Dialog 的可访问语义和焦点恢复能力，但不渲染遮罩或锁定页面。

### ChatAgentLogDialog

继续复用现有运行轨迹 Dialog。运行轨迹本身可以使用模态 Dialog 进入专注查看状态；打开和关闭轨迹不影响浮动 Chat 面板、当前会话或正在进行的运行。

## 多会话模型

浮动面板和 /chat 读取同一个 GET /api/chat/sessions 会话池，不新增 namespace 或独立数据库表。

Provider 维护以下逻辑状态：

~~~ts
type ChatWorkspaceState = {
  sessions: ChatSession[]
  activeSessionId: number | null
  messagesBySession: Record<number, DisplayMessage[]>
  loadingSessions: Set<number>
  runningSessions: Set<number>
  errorsBySession: Record<number, string | null>
}
~~~

实际实现可以采用 Map 或不可变对象，但必须满足：

- 不同会话的消息不能互相覆盖；
- 切换会话时优先显示已缓存内容，不因重新请求出现空白闪烁；
- 没有缓存时只在当前会话内容区显示加载状态；
- 运行中的会话在会话列表中有稳定的运行标志；
- 每个会话同一时刻最多提交一个新的用户请求；
- 切换到其他会话不会取消原会话的流式请求；
- 删除当前会话后切换到相邻会话，若无其他会话则进入新的空会话状态。

创建新会话仍然采用现有行为：用户发送第一条消息时创建并使用标题；点击“新建会话”只切换到空的本地工作区，不提前创建没有消息的数据库记录。

## 流式运行和恢复

一次发送的生命周期：

1. Provider 确认当前会话存在，必要时创建会话；
2. 在对应会话缓存中追加用户消息和空助手消息；
3. 设置该会话为运行中，保留输入框和面板结构；
4. 调用现有 streamChatReply；
5. 通过稳定的事件 ID 和工具调用 ID 增量更新对应会话；
6. 流结束后重新读取会话详情，确保本地状态与持久化消息一致；
7. 刷新会话列表的更新时间和标题；
8. 清除运行状态。

流式事件至少覆盖现有 Chat 已处理的：

- text-delta；
- tool-input-start；
- tool-input-available；
- tool-output-available；
- error。

工具审批继续调用现有审批参数，不在前端另建审批协议。

如果用户关闭面板、切换页面或切换会话，Provider 不取消请求。若用户返回时请求仍在运行，显示会话级思考状态；如果页面刷新导致内存状态丢失，则根据 getChatSession 返回的 is_running 恢复轮询，直到持久化会话结束。

## 浮动面板交互

### 入口

- 右下角固定助手按钮，默认使用现有 /brand/ediora-mark.svg；
- 按钮具有可读的 aria-label 和可见焦点样式；
- 面板打开后保留同一位置的关闭入口；
- 入口只使用 opacity/transform 等不会影响页面布局的动画。

### 面板

- 默认靠右下角固定；
- 默认尺寸约为 380px × 560px；
- 不设置全屏遮罩，不锁定页面滚动；
- 面板内部采用 min-height: 0 的独立滚动区域；
- 会话列表在桌面宽度下可折叠为侧栏，在窄屏下使用面板内的抽屉/覆盖层；
- 消息区和输入区始终保持清晰的上下边界；
- 运行轨迹入口、技能/草稿选择和工具审批都保留在浮动工作区中；
- 需要完整宽屏布局时，可提供打开 /chat 的入口，但不替代浮动面板的完整能力。

### 尺寸调整

- 支持通过边缘或角点调整宽度和高度；
- 位置仍固定在右下角，不支持拖动；
- 最小尺寸保证标题、消息区和输入区可用；
- 最大尺寸不超过视口可用宽高；
- 尺寸保存到版本化的 localStorage key；
- 初始化时按钮不依赖 localStorage；面板首次打开前完成尺寸读取，避免打开瞬间跳变；
- 提供恢复默认尺寸操作；
- 移动端使用视口约束，避免面板超出屏幕。

## 路由切换和无闪烁约束

1. Provider 和 GlobalChatWidget 只能挂在根布局的持久化层，不放到任意页面组件内。
2. 不使用 pathname-based key 或路由变化重置 Chat 状态。
3. 不在路由变化时重新创建会话列表、消息列表或 AbortController。
4. 浮动按钮不依赖会话加载结果，首屏始终拥有固定尺寸。
5. 面板打开后，加载状态只替换面板内部内容，不替换面板节点和尺寸。
6. 已缓存会话在后台刷新期间继续显示旧消息，不先清空再加载。
7. 流式消息按稳定 ID 增量更新，不重建整个会话 DOM 树。
8. 关闭面板只改变可见性，不卸载运行层。
9. Provider 只在真正有 Chat 工作区消费者或首次打开面板时加载会话数据，避免每个页面切换都触发重复请求。

## 错误和恢复

- 会话列表加载失败：保留浮动按钮，面板内显示可重试错误；
- 会话详情加载失败：不清空已有缓存，显示当前会话错误；
- 发送失败：保留用户消息和已收到的助手内容，显示可重试提示并清除运行状态；
- LLM 返回 error 事件：将错误追加到当前助手消息或错误区域，不破坏已完成工具结果；
- 工具审批失败：保持审批信息，允许重新打开会话后继续处理；
- 会话删除返回 404：刷新列表并从本地状态中移除失效会话；
- 页面刷新后发现会话仍运行：显示恢复中的思考状态并按现有恢复机制轮询；
- 面板尺寸存储损坏或超出范围：回退到默认尺寸；
- 不新增静默失败路径，所有用户可恢复错误都必须有界面反馈。

## 页面上下文扩展边界

本次不读取当前页面 DOM，不自动把页面内容、选中内容、草稿或任务塞进 Chat 请求。

Provider 只保留未来可扩展的可选上下文入口，例如：

~~~ts
type ChatPageContext = {
  source?: string
  title?: string
  content?: string
  metadata?: Record<string, unknown>
}
~~~

后续接入页面上下文时，需要明确来源、用户主动触发方式、长度限制和脱敏规则；不能因为组件已经全局挂载就默认收集页面数据。

## 可访问性

- 浮动按钮、关闭按钮、新建会话、会话切换、重命名、删除、调整尺寸都有可读标签；
- 非模态面板打开后保留页面操作，但面板内部仍保持合理的键盘顺序；
- Esc 关闭面板，关闭后焦点回到助手按钮；
- 调整尺寸操作支持鼠标/触摸，并提供键盘可用的恢复默认尺寸；
- 运行状态使用文本和可感知的状态标识，不只依赖旋转图标；
- 错误使用 role=alert 或等价语义。
