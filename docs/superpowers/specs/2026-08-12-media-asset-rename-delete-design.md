# 多媒体资产重命名与删除设计

## 目标

为“创作资产 → 多媒体”补充选中资产后的重命名与删除能力，沿用现有资产更新、删除接口和紧凑媒体网格，不改变预览与上传流程。

## 交互设计

- 用户选中一条多媒体资产后，工作区顶部工具栏在“上传”旁显示“重命名”和“删除”。没有选中的可见媒体时不显示这两个操作。
- 点击“重命名”打开小型 Dialog。输入框预填当前标题并自动聚焦。
- 保存时去除名称首尾空格；空名称不提交，并在 Dialog 内提示“请输入名称。”。
- 保存期间禁用关闭和提交操作。成功后关闭 Dialog，并同步更新媒体网格和当前预览引用中的标题；失败时保留 Dialog，显示“重命名失败，请重试。”。
- 点击“删除”打开二次确认框，提示“删除这个多媒体资产？此操作无法撤销。”。
- 确认删除期间禁用重复操作。成功后从本地资产列表移除该资产，关闭它的预览，并让现有选择逻辑回退到剩余可见资产；失败时保留确认框并显示“删除失败，请重试。”。
- 切换资产类型时关闭未提交的重命名窗口。目录或筛选变化导致原资产不可见时，不显示针对该资产的操作按钮。

## 组件与数据流

- `AssetsClient` 持有重命名 Dialog 状态和现有删除确认状态，调用 `updateCreativeAsset(id, { title })` 与 `deleteCreativeAsset(id)`。
- `MediaAssetGrid` 继续只负责选择与预览，不在卡片内部增加悬浮按钮，避免紧凑缩略图上的遮挡和误触。
- 后端现有 `PATCH /api/assets/{id}` 已支持标题更新；现有 `DELETE /api/assets/{id}` 会删除资产记录，并在上传来源为本地文件时清理对应文件，因此无需新增接口或数据迁移。

## 错误与边界

- 只允许对当前可见且类型为 `media` 的选中资产执行操作。
- 名称仅做非空校验，保持与现有资产标题字段兼容，不引入额外长度或唯一性规则。
- 请求失败不做乐观更新，保留用户输入或确认上下文以便重试。
- 删除不影响由其他记录引用的远程资源；本地上传文件继续由后端既有规则处理。

## 测试与验收

- 操作按钮仅在多媒体页面存在可见选中资产时显示。
- 重命名 Dialog 预填名称；空名称被拦截；成功调用更新接口并刷新卡片标题；失败显示错误并保留 Dialog。
- 删除必须二次确认；成功调用删除接口并移除卡片；失败显示错误并保留确认框。
- 运行 `AssetsClient`、资产 API 与相关媒体网格聚焦测试、目标文件 ESLint，并通过浏览器验证选中、重命名和删除流程。
