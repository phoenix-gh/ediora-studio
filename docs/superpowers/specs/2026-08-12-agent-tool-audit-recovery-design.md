# Agent 工具参数约束与审计恢复设计

## 目标

修复日常创作 Agent 因首次漏传目录导致 `list_creative_asset_candidates` 审计失败的问题，并让最终错误优先反映尚未恢复的真实工具故障。生图接口 404 不在本次范围内。

## 候选资产工具约束

- `list_creative_asset_candidates` 对 Agent 暴露的 MCP schema 将 `directories` 标记为必填。
- 调用方必须传入至少一个目录，例如 `directories: ["女性街拍素材"]`。
- 空数组、空白目录或超过 50 个目录继续由服务层拒绝，不能回退为查询全部资产。
- 服务层与 Python 调用继续兼容旧的单个 `directory` 参数，避免破坏既有非 Agent 调用；该参数不作为 Agent 的首选接口。
- 工具描述明确说明 `directories` 必须来自任务指定的资产目录。

## 审计恢复规则

- 每条工具调用仍完整持久化，失败记录不会删除或改写为成功。
- 最终阻断判断不再采用“任意一次失败即失败”，而是识别已恢复的只读工具失败。
- 一条 `failed` 记录只有同时满足以下条件才视为已恢复：
  - 该调用 `sideEffecting` 为 `false`；
  - 在它之后存在同名工具的 `succeeded` 记录。
- 已恢复失败保留在审计与检查点中，但不阻断任务最终完成，也不参与最终错误选择。
- `uncertain` 永不恢复；有副作用工具的 `failed` 永不恢复；同名工具后续没有成功记录的只读失败仍阻断任务。
- 若存在多个未恢复失败，按实际发生顺序报告第一个未恢复失败。这样候选查询经纠正成功后不会掩盖后续未恢复的 `generateImage` 故障。

## 实现边界

- MCP 函数签名与说明在 `backend/mcp_server.py` 调整，目录归一化与查询逻辑保持不变。
- TypeScript 日常任务在最终化前通过一个纯函数筛选阻断审计，便于独立测试并避免改变持久化流程。
- 不修改通用 Agent 工具执行、幂等 claim、失败写库或生图工具实现。

## 测试与验收

- MCP 工具 schema 将 `directories` 列为 required，同时仍验证服务层 legacy `directory` 兼容路径。
- 无副作用工具失败后同名成功：失败被视为已恢复。
- 无副作用工具只有失败：仍阻断。
- 有副作用工具失败后同名成功：仍阻断。
- `uncertain` 后同名成功：仍阻断。
- 多个审计事件中，最终错误指向第一个未恢复失败。
- 运行日常任务、Agent runtime、MCP 日常创作工具的聚焦测试。
