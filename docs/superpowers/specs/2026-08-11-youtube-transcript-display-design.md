# YouTube 逐字稿展示设计

## 目标

在现有 YouTube 视频列表中提供逐字稿查看入口，复用已经落库的字幕全文和时间分段。此次只补展示能力，不改变字幕提取、Whisper 兜底、分析任务或数据库结构。

## 已有能力

- `YoutubeVideo` 已保存字幕状态、来源、语言、全文、时间分段和错误信息。
- 视频列表 DTO 只返回紧凑字幕状态，不返回大段逐字稿正文。
- `GET /api/youtube/videos/{video_id}/transcript` 已按视频返回完整逐字稿。
- 现有“提取字幕并分析”流程负责生成逐字稿；展示功能不创建新的提取入口。

## 交互设计

### 视频卡片入口

- 当 `transcript_status === "ready"` 时，在视频卡片操作区显示“逐字稿”按钮。
- 按钮与“查看分析”或“重新分析”并列，不在卡片内展开全文，避免破坏视频网格高度。
- 尚未请求、正在提取或提取失败的视频不显示该按钮，继续使用现有分析操作和状态反馈。

### 逐字稿弹窗

- 点击“逐字稿”后打开对话框，并按需请求完整逐字稿接口。
- 加载期间显示明确的加载状态；请求失败时在弹窗内显示安全错误信息，并允许重新请求查看。
- 标题区域显示视频标题，辅助信息显示字幕语言和来源。
- 有非空 `segments` 时按时间顺序展示时间戳和对应文本；点击时间戳在新窗口打开该视频的对应播放位置。
- 没有可用分段但存在 `text` 时展示完整纯文本。
- 提供“复制全文”操作，复制接口返回的 `text`；复制成功和失败均给出明确反馈。
- 弹窗关闭后不改变视频筛选、频道选择或分析状态。

## 数据流

1. YouTube 列表继续通过 `GET /api/youtube/videos` 获取紧凑视频数据。
2. `VideoCard` 仅根据 `transcript_status` 决定是否展示入口。
3. 用户打开弹窗后，前端调用 `GET /api/youtube/videos/{id}/transcript`。
4. 前端在弹窗内渲染元数据、分段或纯文本，并从完整文本执行复制。

前端新增稳定的逐字稿响应类型和查询函数。后端接口与存储不变。

## 时间链接

时间戳以接口中的秒数为准。前端在原视频 URL 上设置 `t=<向下取整后的非负秒数>` 参数，并保留视频原有查询参数。链接使用新窗口打开，不接管当前应用页面。

## 错误与边界

- `ready` 状态下接口仍可能返回空正文；弹窗显示“逐字稿内容为空”，不伪造内容。
- 非法、缺失或负数时间戳不生成可点击时间链接，但对应文本仍展示。
- 未知语言或来源使用原始值；空值显示“未知语言”或“未知来源”。
- 不在本次功能中增加字幕重试按钮、自动轮询、翻译、搜索、编辑或下载文件。

## 测试与验收

- API 单元测试覆盖逐字稿查询函数的路径与响应类型。
- 组件测试覆盖：仅 `ready` 卡片显示入口、打开后按需加载、分段时间戳、纯文本降级、复制全文、空正文和请求失败状态。
- 时间链接测试覆盖已有查询参数、浮点秒数和无效时间戳。
- 运行 YouTube 相关前端测试、相关 ESLint 检查和 `git diff --check`。
- 浏览器验收确认短文本和长文本均在弹窗内可读，长文本独立滚动，关闭弹窗后列表状态保持不变。

## 非目标

- 不修改字幕提取算法、Cookie、代理或语音转写设置。
- 不修改统一情报中心中的 YouTube 原文展示。
- 不改变“提取字幕并分析”“查看分析”“重新分析”的现有语义。
