# 公众号正文采集与历史补全设计

## 背景

当前公众号同步只保存文章标题、链接、封面和摘要。正文由
`GET /wechat/articles/{id}` 在用户第一次查看文章时临时抓取。与此同时，采集代理
通过进程级 `HTTP_PROXY` 和 `HTTPS_PROXY` 生效，而公众号使用的 `httpx` 客户端
默认读取这些环境变量。因此启用 SOCKS 采集代理后，查看正文会误走代理，并可能因
运行环境未安装 `socksio` 而失败。

当前数据库共有 574 篇公众号文章，其中 472 篇正文为空。

## 网络边界

公众号的扫码登录、账号搜索、文章列表、文章正文和公众号图片抓取全部使用直连，
不得读取 `HTTP_PROXY`、`HTTPS_PROXY` 或系统代理。实现上，公众号采集相关的
`httpx.AsyncClient` 统一显式设置 `trust_env=False`。

该规则只适用于公众号只读采集链路。公众号官方发布 API 和已存在的 SSH 发布隧道
不在本次修改范围内。

## 采集流程

每次同步单个公众号时：

1. 从公众号后台获取最新文章列表；
2. 新文章先保存或更新元数据；
3. 查询该公众号所有正文为空的文章，包括历史记录和本次新增记录；
4. 使用复用的直连 HTTP 客户端抓取正文；同一账号最多同时抓取 3 篇，每批完成后
   再开始下一批；
5. 每篇正文抓取成功后写入数据库，失败则保留空正文并记录失败原因；
6. 完成后提交本次成功写入的元数据和正文。

下一次手动或定时采集会尝试补齐现有 472 篇空正文。由于需要访问大量微信文章，
第一次补全可能持续较长时间；单篇失败不得中断同一账号或其他账号的采集。

## 状态与错误

单账号同步结果增加正文成功数和正文失败数。手动采集状态与定时采集日志汇总这些
数字：只要存在正文失败，采集结果为警告。日志详情按处理顺序保留前 20 条失败，
每条包含文章标题和异常文本；超过 20 条时附加剩余失败数量。元数据采集成功不能
掩盖正文失败。

查看文章详情只读取数据库，不再触发外部网络请求。正文为空时返回现有文章数据，
前端显示“正文尚未采集成功”，避免把查看动作变成隐式采集任务。

## 测试与验收

- 验证公众号采集客户端在存在 SOCKS 环境变量时仍使用 `trust_env=False`；
- 验证同步新文章时保存正文；
- 验证同步会补齐同账号已有的空正文；
- 验证单篇正文失败会继续处理其他文章并进入警告统计；
- 验证文章详情接口不会调用正文抓取函数；
- 运行公众号聚焦后端测试，并通过真实采集状态日志确认不再出现 `socksio` 错误。

## 非目标

- 不为全局 SOCKS 代理安装或补充依赖；
- 不改变 X、Reddit、YouTube、GitHub、论文等其他采集源的代理策略；
- 不修改公众号发布 API、SSH 隧道或草稿发布流程；
- 不删除正文抓取失败的文章元数据。
