# 任务看板统一日志列表设计

## 背景

当前任务看板同时渲染“运行日志”和“全部任务”。前者来自 `DailyCreationRun`，后者来自 `ContentJob`；定时创作的一次执行同时存在于两套数据中，因此用户会看到重复日志。日志详情又分别从定时运行接口和通用 Job 接口加载，增加了维护成本。

## 目标

- 页面只保留一套任务日志列表。
- 以 `ContentJob` 作为任务日志的唯一展示实体，定时任务通过标签和关联信息区分。
- 日志列表支持筛选和滚动加载，避免一次请求和渲染过多历史任务。
- 点击任务后继续使用对话框查看步骤、事件、Agent 完整消息和工具记录。
- 保留顶部仪表盘、规则安排和规则操作，不改变任务执行语义。

## 页面结构

任务看板从上到下分为三层：

1. 顶部“今日概览”仪表盘。
2. “创作规则”区域，继续展示规则、启用状态、下一次执行时间和手动运行入口。
3. “任务日志”区域，取代“运行日志”和“全部任务”两个区块。

任务日志列表使用紧凑行卡片，每行显示：任务标题、Job ID、任务类型、定时规则/计划时间（如果有关联）、创建时间、当前步骤、状态、产出数量（如果可用）和“查看日志”操作。定时任务不再额外渲染一份运行记录；调度日志不作为独立列表展示，关联的失败信息进入任务行或详情对话框。

筛选器：

- 全部任务
- 定时任务
- 手动任务
- 执行中
- 已完成
- 失败

筛选发生变化时清空当前列表并从第一页重新加载。列表底部保留可见的“加载更多”按钮作为 IntersectionObserver 自动加载失败或键盘操作时的兜底。

## 数据与接口

将通用 Job 列表接口扩展为游标分页：

```text
GET /api/jobs?limit=30&cursor=<opaque>&kind=scheduled|manual&status=<status>
```

响应：

```json
{
  "jobs": [],
  "next_cursor": "...",
  "has_more": true
}
```

排序固定为 `created_at DESC, id DESC`。游标由后端生成，前端不解析其内容。服务端在查询层完成类型和状态筛选，并对 `limit` 做安全范围限制。

定时任务的规则信息由 Job 列表 payload 提供：`run_id`、规则名称、触发类型和计划时间。这样前端无需再把 `DailyCreationRun` 列表与 Job 列表做客户端拼接，也不会因为两套列表刷新时序不同产生重复项。

详情统一使用：

```text
GET /api/jobs/{job_id}/agent-log
```

详情接口只在打开对话框时请求，继续展示脱敏后的 Agent 消息、工具记录、步骤和事件。

## 前端状态与滚动加载

新增或重构为 `TaskLogList` 组件，由组件自己管理：

- 当前筛选条件
- 已加载任务，按 Job ID 去重
- `next_cursor` / `has_more`
- 首次加载、追加加载和错误状态
- 详情对话框选中的 Job

任务状态轮询只刷新第一页，并通过 Job ID 合并到已加载列表，不覆盖已经加载的历史页。用户执行取消、重试等操作后触发第一页刷新；筛选条件变化则重置全部分页状态。

滚动容器使用固定最大高度和 `overflow-y-auto`，底部 sentinel 进入可视区时触发下一页请求。追加请求期间不重复触发；没有更多数据时显示“已加载全部任务”。

删除 `CreationRunLog` 在任务看板中的展示职责，`JobLogDialog` 作为唯一详情对话框入口。旧组件是否物理删除以实现阶段的引用检查结果为准，不保留第二套日志列表。

## 错误与兼容

- 首次列表请求失败显示错误状态和“重新加载”。
- 追加请求失败保留已加载内容，并在列表底部提供“重试加载”。
- 没有任务时显示空状态，不显示重复的占位区域。
- 旧任务仍可通过通用 Job 详情接口打开；没有 Agent 执行记录时显示“暂无 Agent 消息”。
- 现有 `CreationDashboard` 的规则和汇总接口保持兼容；`scheduler_logs` 可以继续由后端返回，但不再由任务看板单独渲染。

## 测试计划

后端：

- 验证默认分页、游标分页和稳定排序。
- 验证定时/手动类型筛选和状态筛选。
- 验证分页响应字段及定时任务关联信息。
- 验证旧的 Job 详情和 Agent 日志接口不受影响。

前端：

- 首次加载、空状态、失败重试。
- 滚动触发追加加载、追加请求去重和“已加载全部”状态。
- 筛选条件变化会重置列表并请求对应参数。
- 任务详情仍通过对话框打开，并加载完整 Agent 日志。
- 取消/重试后第一页刷新不会产生重复任务。

## 不在本次范围

- 不改变任务执行、调度、重试或 Agent 工具调用规则。
- 不把完整模型消息直接放进列表响应。
- 不新增抽屉式详情；详情继续使用对话框。
