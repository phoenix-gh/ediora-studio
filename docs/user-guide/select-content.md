# 选择值得创作的内容

采集到内容并不代表每一条都值得写。先读懂发布记录，再判断它是否适合当前账号；确定值得立即创作时，直接从记录创建稿件。

## 完成后你将得到什么

完成本章后，你会选定一条适合创作的 GitHub 发布记录，并打开“创建稿件”窗口；不需要立即创作的热门项目，也可以先保存为写作线索。

## 开始前的准备

- **信息源 → GitHub** 中至少有一个跟踪仓库；
- 该仓库的“发布”标签中已经出现发布记录；
- **设置 → 发布账号** 中有启用账号；
- **创作 → 写作模板** 中有可用模板。

如果还没有发布记录，先参阅[采集可用于创作的内容](collect-content.md)。

## 阅读发布记录

1. 打开 **信息源 → GitHub**，从左侧选择一个仓库，再打开“发布”标签。
   页面会列出该仓库的版本标签、发布名称、发布时间和 Changelog 摘要。

2. 点击“查看完整 Changelog”阅读被折叠的内容。
   展开后，你应该能够判断这次发布增加了什么、修复了什么，以及是否会影响目标读者。

3. 需要核对原始信息时，点击“在 GitHub 查看”。
   原始发布页会在新窗口打开。核对完成后回到 Ediora，继续选择是否创作。

> **提示：** 带有“Pre-release”标记的版本可能仍处于预发布阶段。写作前应在正文中准确说明版本性质，不要把它描述成稳定正式版。

## 判断是否值得创作

可以使用下面的简短检查表：

- 这次发布是否有清晰的新功能、重要修复或使用方式变化？
- 内容是否符合当前发布账号的定位和受众？
- 是否能从 Changelog 或原始页面核实关键事实？
- 是否有一个具体角度，而不只是重复发布说明？
- 现在写是否有时效价值？

满足前三项，并且你能说清文章角度时，通常适合直接创建稿件。信息不完整、与账号无关或只有微小维护变化的记录，可以先跳过。

## 直接创建稿件

1. 在选定的发布记录底部点击“创建稿件”。
   页面会打开同名窗口，并提示选择账号和写作方案。

2. 选择一个启用的“发布账号”和一个“写作方案”。
   账号决定目标读者和表达约束，写作方案决定文章结构与创作方法。

3. 首次创作建议暂时取消“同时配封面”。
   这样可以先验证文字创作主线；确认图片模型可用后，再在以后的任务中同时生成封面。

4. 点击“创建创作任务”。
   成功后会看到“已创建创作任务”提示，以及可进入任务看板的“查看看板”操作。

> **提示：** “创建创作任务”表示任务已经排入处理流程，不表示草稿已经生成。后续需要在任务看板等待任务完成。

## 保存为写作线索

“热门趋势”列表中的项目可以先保存为线索，不必立即创建稿件。这个操作适合有潜力、但还需要补充资料或等待更好角度的内容。

1. 在 GitHub 页面打开“热门趋势”。
   每个项目右侧会显示星标变化和一个书签形状的操作按钮。

2. 点击“加为写作方案线索”。
   选择目标写作方案；如果该方案已有进行中的草稿，还可以选择同时关联草稿。

3. 按需补充备注，然后点击“添加”。
   成功后会看到“已加到写作方案”或“已加到写作方案和草稿”的提示，按钮状态会变为“已加为线索”。

> **注意：** GitHub 发布记录使用“创建稿件”进入创作任务；“加为写作方案线索”位于“热门趋势”列表。两者不是同一个入口。

## 常见问题

### 点击“创建稿件”后一直显示加载中

通常是发布账号或写作方案尚未加载完成。稍等片刻；如果选择列表仍为空，先确认至少有一个启用账号和一个写作模板，然后关闭窗口重新打开。

### 创建按钮不可用

必须同时选择发布账号和写作方案。任意一项为空时，“创建创作任务”不会执行。

### 不确定应该直接创作还是保存线索

已经有明确事实、账号匹配且角度清晰时直接创建稿件；只是觉得项目值得关注，但还说不清写什么时，先保存为线索。

## 下一步

成功创建任务后，前往 **任务看板** 查看进度。后续章节会说明如何等待任务完成并找到生成的草稿。
