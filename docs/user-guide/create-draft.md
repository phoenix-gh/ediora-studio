# 创建草稿

从 GitHub 发布记录点击“创建稿件”后，Ediora 会先创建一项创作任务，再把完成的结果保存到草稿箱。这两个阶段是分开的：看到任务创建成功，并不代表草稿已经生成。

## 完成后你将得到什么

完成本章后，你将拥有一篇由选定 GitHub 发布记录生成的草稿，并能在 **草稿箱** 中打开它继续编辑。

## 开始前的准备

- 已完成[首次创作所需配置](setup.md)；
- 已在 GitHub 仓库的“发布”标签中[选定值得创作的记录](select-content.md)；
- 至少有一个启用的发布账号和一个写作模板；
- “文字默认 Adapter”的连接测试成功。

## 从 GitHub 发布记录创建稿件

1. 打开 **信息源 → GitHub**，从左侧选择目标仓库，再打开“发布”标签。
   页面会显示该仓库的发布记录。

2. 找到目标记录，核对版本标签和 Changelog，然后点击“创建稿件”。
   页面会打开“创建稿件”窗口，并显示当前版本标签。

## 选择发布账号和写作模板

1. 在“发布账号”中选择本次内容面向的账号。
   账号画像会影响文章受众、语气、选题边界和篇幅要求。

2. 在“写作方案”中选择与本次内容最接近的写作模板。
   模板决定文章结构和创作方法。列表为空时，先回到 **创作 → 写作模板** 新建并保存一个模板。

3. 决定是否勾选“同时配封面”。
   第一次验证文字流程时建议取消；只有图片模型已经配置并测试成功时，才同时生成封面。

4. 点击“创建创作任务”。
   成功后会显示“已创建创作任务”，并提供“查看看板”操作。

> **提示：** 记录成功提示中的任务编号。后续可以用编号在任务日志中确认你正在查看同一项任务。

## 在任务看板等待结果

1. 点击成功提示中的“查看看板”，或者从主导航打开 **任务看板**。
   在“任务日志”中，你应该能看到刚创建的手动任务。

2. 查看任务状态。
   “排队中”和“执行中”表示还需要等待；不要因为草稿箱暂时没有结果就重复创建任务。

3. 需要了解进度时，点击“查看日志”，打开“任务概览”。
   页面会列出当前步骤；任务显示“已完成”后再进入草稿箱。

4. 如果任务失败，先阅读错误并修正原因。
   失败步骤允许重试时才会显示“重试”。具体处理方式参阅[查看和管理创作任务](task-management.md)。

## 在草稿箱找到结果

1. 任务显示“已完成”后，从主导航打开 **创作 → 草稿箱**。
   左侧列表会显示草稿标题、状态、类型和更新时间。

2. 把“按主题筛选”和“按状态筛选”分别设为“全部主题”和“全部状态”。
   这样可以避免新草稿被已有筛选条件隐藏。

3. 根据任务主题和更新时间找到最新草稿，然后点击它。
   右侧编辑区会显示标题、正文、关联写作模板和当前状态。

4. 确认标题与正文不为空。
   看到完整内容后，说明从发布记录到草稿的主流程已经完成。

如果任务已完成却找不到草稿，不要立即重建任务。先按照[常见问题排查](troubleshooting.md#没有找到生成的草稿)检查筛选条件和任务最后一步。

## 也可以手动发布创作任务

没有合适的 GitHub 发布记录时，可以直接从 **今日工作台** 创建任务。

1. 打开 **今日工作台**，点击“发布创作任务”。
   页面会打开同名窗口。

2. 选择发布账号，填写“主题”，并选择评论、教程、故事或测评体裁。
   “想法与素材”和“备注”可以留空；填写时应提供文章角度、事实线索或明确限制。

3. 点击“发布”。
   成功后会看到“已创建创作任务”和任务编号。后续仍然通过 **任务看板 → 草稿箱** 查找结果。

## 常见问题

### 创建窗口没有发布账号

回到 **设置 → 发布账号**，确认账号已经保存并显示“启用”，然后重新打开创建窗口。

### 写作方案列表为空

打开 **创作 → 写作模板**，新建一个模板并保存。GitHub 发布记录的直接创作流程必须选择写作方案。

### 任务完成后草稿标题与预期不同

任务会根据发布记录、账号画像和写作模板生成标题。打开草稿后可以直接修改标题和正文，保存前完成事实核对即可。

## 下一步

草稿出现后，继续阅读[编辑草稿并完成发布前准备](edit-and-prepare.md)，检查内容、素材和目标平台格式。
