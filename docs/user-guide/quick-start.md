# 快速上手：从 GitHub 发布记录到可发布草稿

这条快速上手路线只做一件事：选择一条 GitHub Release，创建内容任务，并在草稿箱得到一篇完成发布前检查的草稿。第一次操作时建议先走通纯文字流程，不同时生成封面。

## 完成后你将得到什么

你将得到一篇：

- 来源明确，能够回到原始 GitHub Release 核对；
- 已按指定发布账号和写作模板生成；
- 已完成标题、事实、链接和平台格式检查；
- 状态为“待发布”且没有未保存修改的草稿。

本流程不要求你立即把内容发布到外部平台。

## 开始前的准备

准备一个近期有 Release 的公开 GitHub 仓库，然后确认：

- **设置 → AI 大模型** 中已经保存“文字默认 Adapter”；
- **设置 → 发布账号** 中至少有一个启用账号；
- **创作 → 写作模板** 中至少有一个可选模板；
- 文字模型的“测试连接”已经成功。

还没有完成这些项目时，先阅读[完成首次创作前的准备](setup.md)。

## 1. 完成最低配置

1. 打开 **设置 → AI 大模型**，确认支持文本的 Adapter 已被指定为“文字默认 Adapter”。
   **预期结果：** 用途分配中显示选定的文字 Adapter，并且连接测试成功。

2. 打开 **设置 → 发布账号**，确认目标账号显示“启用”。
   **预期结果：** 账号出现在列表中，后续创建窗口可以选择它。

3. 打开 **创作 → 写作模板**，确认至少有一个已保存模板。
   **预期结果：** 模板出现在左侧列表，打开后没有“未保存”提示。

配置字段和创建模板的详细说明参阅[完成首次创作前的准备](setup.md)。

## 2. 找到一条 GitHub 发布记录

1. 打开 **信息源 → GitHub**，点击“订阅管理”。
   输入 `owner/repo` 或完整 GitHub URL，然后点击“添加”。
   **预期结果：** 仓库出现在左侧“跟踪仓库”中，并自动进入该仓库的“发布”标签。

2. 如果页面显示“暂无发布记录”，点击一次“刷新”。
   **预期结果：** 页面出现一条或多条发布记录，并显示版本标签、名称和 Changelog 摘要。

3. 展开一条内容清晰的记录，必要时点击“在 GitHub 查看”核对原始发布页。
   **预期结果：** 你能够说清这次发布改变了什么，以及为什么适合当前账号。

添加仓库、刷新和成功判断参阅[采集可用于创作的内容](collect-content.md)。

## 3. 创建稿件

1. 在选定发布记录底部点击“创建稿件”。
   **预期结果：** 页面打开“创建稿件”窗口，并显示当前版本标签。

2. 选择一个“发布账号”和一个“写作方案”。第一次使用时取消“同时配封面”。
   **预期结果：** 两个选择项都有明确值，“创建创作任务”按钮可以点击。

3. 点击“创建创作任务”。
   **预期结果：** 页面显示“已创建创作任务”、任务编号和“查看看板”操作。

> **提示：** 任务创建成功不等于草稿已经生成。不要再次点击创建；下一步是等待同一个任务完成。

如何判断内容价值以及何时保存为线索，参阅[选择值得创作的内容](select-content.md)。

## 4. 在任务看板确认进度

1. 点击成功提示中的“查看看板”，或者从主导航打开 **任务看板**。
   **预期结果：** “任务日志”中出现刚创建的手动任务，标题和任务编号与成功提示一致。

2. 等待任务从“排队中”或“执行中”变为“已完成”。
   **预期结果：** 任务状态显示“已完成”，不再显示“取消”。

3. 需要确认细节时点击“查看日志”，打开“任务概览”。
   **预期结果：** 执行步骤没有未处理的失败；如果失败，可看到具体错误和允许重试的步骤。

任务状态、取消和安全重试参阅[查看和管理创作任务](task-management.md)。

## 5. 在草稿箱检查结果

1. 打开 **创作 → 草稿箱**。
   **预期结果：** 左侧列表显示新生成的草稿及其更新时间。

2. 如果没有立即看到，把主题和状态筛选都改为“全部”。
   **预期结果：** 列表重新加载，不再因筛选条件隐藏新草稿。

3. 点击与任务主题和时间匹配的草稿。
   **预期结果：** 右侧显示非空标题、完整正文、关联写作模板和当前草稿状态。

创建任务、等待结果和查找草稿的完整说明参阅[创建并找到一篇草稿](create-draft.md)。

## 6. 编辑并完成发布前检查

1. 把草稿状态改为“编辑中”，核对并修改标题和正文。
   **预期结果：** 工具栏显示“有未保存修改”，“保存”按钮变为可用。

2. 检查版本号、产品名、数字、原始链接和文章角度，然后点击“保存”。
   **预期结果：** 页面提示“已保存”，“有未保存修改”消失。

3. 打开“素材”，确认来源和图片状态；再打开“发布”，查看目标平台预览和要求。
   **预期结果：** 你能够确认来源有效、图片是否齐全，以及外部发布还需要哪些账号或格式准备。

4. 关闭预览，修正发现的问题，把草稿状态改为“待发布”，再次点击“保存”。
   **预期结果：** 草稿显示“待发布”，页面没有未保存提示。

完整发布前检查表参阅[编辑草稿并完成发布前准备](edit-and-prepare.md)。到这里，首次核心流程已经完成。

## 如果流程没有按预期进行

- 模型或图片配置问题：检查 **设置 → AI 大模型**；
- GitHub 没有发布记录：确认仓库确实有 Release，再执行一次同步或刷新；
- 任务长时间不完成：进入 **任务看板 → 查看日志 → 任务概览**；
- 任务已完成但找不到草稿：清除草稿箱筛选，再核对任务最后一步；
- 发布账号不可选：确认账号已经保存并显示“启用”。

按现象逐项处理时，参阅[常见问题排查](troubleshooting.md)。

## 接下来可以做什么

核心流程走通后，可以继续完善写作模板和账号画像，或者在使用文档中选择文字视频、数字人口播等进阶创作流程。
