# 内容采集

Ediora 可以跟踪 GitHub 仓库并读取它们的发布记录。首次使用时，先添加一个近期有 Release 的仓库，再确认内容已经出现在“发布”标签中。

## 完成后你将得到什么

完成本章后，你将在 **信息源 → GitHub** 中看到一个跟踪仓库，以及该仓库的一条或多条发布记录。这些记录可以直接用于创建稿件。

## 开始前的准备

- 已经能够正常进入 Ediora；
- 已准备一个公开的 GitHub 仓库地址，例如 `owner/repo`；
- 目标仓库近期确实发布过 Release。

如果还没有完成模型、账号和写作模板配置，先参阅[完成首次创作前的准备](setup.md)。

## 打开 GitHub 信息源

1. 从主导航打开 **信息源 → GitHub**。
   页面左侧会显示“GitHub 雷达”“热门趋势”和“跟踪仓库”。

2. 先查看左侧是否已经存在目标仓库。
   如果仓库已经存在，点击仓库名称，页面会选中该仓库，并允许打开“发布”标签；如果不存在，继续下一节添加。

## 添加或选择仓库

1. 点击“GitHub 雷达”右侧的“订阅管理”按钮。
   页面会打开“订阅管理 · GitHub”窗口，并列出当前已订阅的仓库。

2. 在仓库输入框中填写 `owner/repo` 或完整 GitHub URL。
   “分组”和采集间隔可以保留默认值；它们不会影响本次手动确认发布记录。

3. 点击“添加”。
   添加成功后，仓库会同时出现在“已订阅”和左侧“跟踪仓库”列表中，页面会选中该仓库并进入“发布”标签。

4. 如果仓库已经订阅，也可以在订阅管理中点击该仓库的“同步”。
   看到“后台同步已启动”的提示，表示系统已经接受同步请求；发布记录可能需要稍等片刻才会出现。

> **提示：** 添加仓库后立即关闭订阅管理不会取消采集。回到仓库的“发布”标签检查结果即可。

## 刷新发布记录

1. 在左侧点击目标仓库，然后打开“发布”标签。
   页面顶部会显示当前发布记录数量。

2. 如果页面显示“暂无发布记录”，点击右上角“刷新”。
   刷新期间按钮会显示加载状态。完成后，页面会重新读取该仓库的 Releases。

3. 等待刷新结束。
   采集成功时，空状态会被发布记录列表替代；每条记录会显示版本标签、名称、发布时间和 Changelog 摘要。

> **注意：** 不要连续快速点击“刷新”。一次刷新尚未结束时重复操作不会让内容更快出现，还会增加外部服务访问次数。

## 确认采集成功

下面三项同时满足时，可以认为首次采集已经完成：

- 左侧“跟踪仓库”中能看到目标仓库；
- 选中仓库后，“发布”标签显示的数量大于 0；
- 列表中至少有一条可以展开 Changelog 或点击“在 GitHub 查看”的发布记录。

如果只看到“热门趋势”，确认已经先从左侧选择具体仓库。“热门趋势”是单独的内容列表，不等同于某个仓库的发布记录。

## 常见问题

### 输入仓库后无法添加

使用 `owner/repo` 或完整的 `https://github.com/owner/repo` 地址，避免只填写仓库名称。还要确认仓库可以从当前网络访问。

### 刷新后仍然显示“暂无发布记录”

先在 GitHub 网站确认该仓库是否真的发布过 Release。只有提交记录或标签、但没有 Release 的仓库，不会产生这里需要的发布记录。必要时换用一个近期有正式 Release 的公开仓库。

### 出现访问频率限制

等待限制恢复后再试；如果经常遇到限制，可以在 **设置 → GitHub API** 中配置可用令牌。不要把令牌写进仓库地址、草稿或备注。

## 下一步

发布记录出现后，继续阅读[选择值得创作的内容](select-content.md)，从列表中挑选一条适合当前账号的更新。
