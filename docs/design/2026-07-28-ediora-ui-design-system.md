# Ediora 全站 UI 设计体系

日期：2026-07-28

状态：视觉方向与交互原则已确认，待实施
视觉方向：A · 智性靛蓝

## 1. 背景

Ediora 目前同时存在以下问题：

- 全局主题仍以 shadcn 默认黑白色为主，业务页面又分别硬编码 `zinc`、`indigo`、`sky`、`violet`、`green`、`orange` 等颜色。
- 业务层大量混用原生控件和公共 UI 组件，按钮、输入框、选择器、列表项和弹窗的高度、圆角、焦点态不一致。
- 页面标题、辅助文字和元信息使用过多 9–11px 字号，信息层级碎片化。
- 同类页面拥有不同的二级栏宽度、顶部工具栏、阅读器宽度和滚动方式。
- 暗色变量、字体变量与通知主题未形成完整闭环。
- 临时操作容器不统一，存在应用 Dialog、手写弹窗和浏览器原生弹窗并存的情况。

这次重构不是单纯换色，而是建立“设计令牌 → 公共组件 → 页面模板”三层体系，再逐步迁移现有页面。

## 2. 目标与非目标

### 2.1 目标

1. 建立一致、专业、克制且有适度 AI 科技感的品牌视觉。
2. 让同类信息在不同页面拥有相同的层级、状态和交互反馈。
3. 将全站页面收敛为五类可复用页面模板。
4. 完整统一 Light / Dark 主题映射、字体、控件尺寸和焦点状态。
5. 通过共享组件降低页面内重复 Tailwind 类和手写交互。
6. 保持高信息密度，但不再依赖过小字号实现紧凑布局。

### 2.2 非目标

- 不修改采集、分析、创作、任务与发布的业务流程。
- 不重做菜单信息架构和现有路由。
- 不把“待响应”扩展为通用 Todo 系统。
- 不改变 `generateImage` 的纯提示词契约。
- 不改变多媒体资产的紧凑网格与双击 Dialog 预览方式。
- 不把业务配置迁移到侧边抽屉。
- 不在 UI 重构中顺带替换后端接口、数据库或任务系统。

## 3. 设计原则

### 3.1 任务优先

视觉层级服务于“发现信息 → 判断价值 → 形成素材 → 创作 → 发布”的工作流。装饰不能压过内容和操作。

### 3.2 一种语义，一种表达

- 靛蓝只代表主要交互和当前选择。
- 青色只代表采集、连接、数据与信息流。
- 紫色只代表 AI 能力和 AI 生成结果。
- 红、黄、绿只代表错误、警告和成功。
- 平台品牌色仅用于平台图标或小面积身份识别，不能成为页面主操作色。

### 3.3 稳定工作区

用户打开配置、素材选择、工作流或发布流程时，底层编辑区的宽度和位置不发生变化。临时任务统一使用 Dialog。

### 3.4 中等密度

默认使用 14px 正文和 12px 辅助信息。紧凑页面通过间距和控件高度实现密度，不再使用 9–11px 正文。

### 3.5 失败可恢复

错误反馈必须保留当前输入、筛选条件和选中项；支持局部重试时不得清空整页上下文。

## 5. 字体与排版

### 5.1 字体

- UI 中文：系统中文无衬线字体栈。
- 英文与数字：Geist Sans。
- 代码与技术字段：Geist Mono。
- `--font-sans` 必须正确指向 `--font-geist-sans`，不能自引用。

### 5.2 层级

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Page Title | 28 / 34 | 700 | 页面主标题 |
| Section Title | 18 / 26 | 650 | 页面区块标题 |
| Item Title | 14 / 20 | 600 | 列表标题、卡片标题 |
| Body | 14 / 22 | 400 | 表单、说明、正文摘要 |
| Meta | 12 / 18 | 400–500 | 时间、计数、来源、状态辅助信息 |

仅在极窄标签或图表刻度中允许 11px；不得再将 9–11px 用作普通正文。

## 6. 尺寸、圆角与间距

### 6.1 控件高度

- `control-sm`: 32px，用于高密度工具栏。
- `control-md`: 36px，默认按钮、输入框和选择器。
- `control-lg`: 40px，用于主要表单提交和重要操作。

### 6.2 圆角

- `radius-control`: 8px。
- `radius-panel`: 12px。
- `radius-dialog`: 16px。
- Pill 仅用于状态标签、计数和单一选择状态。

### 6.3 间距

- 采用 4px 基线。
- 页面横向内边距：28px；窄屏降至 20px。
- 主要区块间距：24px。
- 表单字段间距：16px。
- 紧凑列表行最小高度：56px；标准列表行最小高度：64px。

## 7. 应用外壳

### 7.1 一级侧栏

- 桌面宽度固定 224px。
- 品牌区、主工作流、创作、信息源和设置拥有稳定分组。
- 当前路由使用 `primary-subtle` 背景、`primary` 图标与文字。
- Hover 仅使用中性背景。
- 平台图标可保留原色，菜单文字不跟随平台色。

### 7.2 页面容器

- 根布局负责唯一一次侧栏偏移和视口高度。
- 页面内部不得再次使用 `ml-56` 或独立 `h-screen`。
- 每个主要区域自己声明滚动，避免根布局与页面产生嵌套滚动。
- 页面标题和主要操作统一由 `PageHeader` 承载。

### 7.3 主题

- 默认跟随系统。
- 设置页提供 System / Light / Dark 三项选择。
- 页面、Dialog、Popover、Toast 与编辑器必须使用同一主题来源。

## 8. 五类页面模板

### 8.1 概览 / 任务页

适用：今日工作台、今日计划、创作任务。

结构：

1. `PageHeader`
2. 可选告警横幅
3. 核心指标或摘要
4. 主要任务队列
5. 次级信息区

禁止用大量同质卡片填满页面。卡片只表达有独立边界的内容集合。

### 8.2 信息源页

适用：GitHub、YouTube、V2EX、Reddit、X 等。

结构：

1. 一级侧栏 224px
2. 可选 `SourceRail` 240px
3. `WorkspaceToolbar` 56–64px
4. 列表、媒体网格或内容流
5. 可选阅读 Dialog 或统一阅读器

各平台保留内容形态差异，但标题、筛选、采集、订阅管理和状态反馈位置一致。

### 8.3 创作工作台

适用：草稿箱、写作模板、创作资产、数字人口播、AI 助手、待响应。

默认结构：

- 左侧列表约 25%，最小 280px，最大 360px。
- 右侧主编辑区约 75%。
- 主编辑区宽度保持稳定。
- 素材、工作流、发布和配置使用 Dialog。

创作资产继续保留文章列表与 Markdown 编辑器；多媒体继续使用紧凑网格和双击 Dialog 预览。

### 8.4 内容阅读页

适用：公众号、掘金、36 氪、论文等需要长文阅读的页面。

- 内容流与阅读器共用统一骨架。
- 阅读器标准宽度为 460px。
- 阅读器可关闭，正文滚动与列表滚动分离。
- 阅读器内部使用统一 `ArticleReader` 排版。

### 8.5 设置页

- 设置导航固定 240px。
- 表单内容列最大宽度 760px。
- 每组配置使用 `FormSection`。
- 保存、测试与帮助文字拥有固定位置。
- 密钥字段统一掩码、显示切换与配置状态。

## 9. 临时交互容器

### 9.1 Inline

适合标题、正文、状态、单个开关与少量筛选。

### 9.2 Popover

适合排序、日期范围、单选菜单和少量快捷选项。Popover 不承载长表单或多步骤任务。

### 9.3 Dialog

桌面端业务临时任务统一使用 Dialog：

- Small，最大宽度 480px：确认、重命名、单字段新增、简单配置。
- Medium，最大宽度 720px：素材选择、账号配置、筛选规则、标准表单。
- Large，最大宽度 960px：工作流、发布预览、多步骤任务、媒体浏览。

移动端 Dialog 接近全屏，但仍保留明确标题、关闭入口和底部操作区。

### 9.4 AlertDialog

删除、覆盖和不可逆操作使用 AlertDialog，文案明确说明对象和影响。

### 9.5 明确禁止

- 不使用浏览器原生 `prompt`、`confirm`、`alert`。
- 桌面端不使用业务侧边抽屉。
- 不使用手写遮罩层模拟 Dialog。

## 10. 公共组件

### 10.1 基础组件

在现有 `components/ui` 基础上统一：

- `Button`
- `Input`
- `Textarea`
- `Select`
- `Tabs`
- `Badge`
- `Card`
- `Dialog`
- `AlertDialog`
- `Popover`
- `Tooltip`
- `Skeleton`
- `Toast`

### 10.2 业务布局组件

- `AppShell`：一级导航、主内容偏移与主题容器。
- `PageHeader`：标题、描述、计数、主操作。
- `WorkspaceToolbar`：筛选、搜索、视图切换和操作区。
- `SourceRail`：信息源二级导航。
- `SplitWorkspace`：列表与编辑器的稳定比例和滚动边界。
- `ContentListRow`：统一选中、Hover、元信息和操作。
- `ArticleReader`：统一长文阅读器。
- `FormSection`：设置页表单分组。
- `StatusBadge`：任务、采集、AI 与业务状态。
- `AsyncState`：加载、空状态、失败和重试。

## 11. 组件状态

### 11.1 选中与 Hover

- 当前选中：`primary-subtle` 背景 + 左侧 3px `primary` 标记。
- Hover：仅使用中性背景，不使用品牌色边框。
- Focus：所有可键盘操作控件显示统一主色 Focus Ring。

### 11.2 Loading

- 按钮 Loading 保留原宽度并显示 Spinner。
- 列表和页面首次加载使用与真实布局一致的 Skeleton。
- 后台任务提交后允许离开当前页面，通过 Toast 和任务中心继续追踪。

### 11.3 Disabled

- 使用明确的弱化前景和背景，不仅依赖透明度。
- 禁用时保留 Tooltip 或辅助文字说明原因。

## 12. 反馈与错误处理

| 场景 | 反馈方式 |
| --- | --- |
| 单字段校验失败 | 字段下方内联错误 |
| 表单整体提交失败 | Dialog / 表单顶部错误摘要 + 字段错误 |
| 页面级连接或授权问题 | 页面横幅，提供设置或重试操作 |
| 后台任务提交成功或失败 | Toast，提供“查看任务”动作 |
| 空数据 | `AsyncState` 空状态，解释原因并给出主操作 |
| 内容加载失败 | 当前区域失败态，保留筛选和选中上下文，可局部重试 |
| 删除与覆盖 | AlertDialog |

Toast 不承载用户必须长期记住的信息；重要错误必须留在页面上下文中。

## 13. 数据与交互边界

- 服务端页面继续负责初始数据加载，客户端组件负责筛选、选择、Dialog 和局部更新。
- 设计系统组件只接收显示状态和事件，不直接调用业务 API。
- 页面容器负责将 API 状态转换为 `AsyncState`、`StatusBadge` 和反馈组件。
- Dialog 关闭后，焦点回到触发按钮；取消操作不修改底层表单和列表状态。
- 保存失败时保留用户编辑内容。
- 列表刷新后尽量保留当前选中项；对象不存在时才选择第一个可用项。

## 14. 响应式规则

- 主要验收视口：1440×1000、1280×800、1024×768。
- 1280px 以下允许收紧页面横向内边距和二级栏宽度。
- 1024px 以下一级侧栏可切换为紧凑图标模式，二级栏可通过 Dialog 选择来源。
- 多栏页面不得产生页面级横向滚动。
- 业务操作在窄屏仍使用 Dialog，不改为侧边抽屉。

## 15. 迁移顺序

1. 修正全局字体与 Light / Dark 语义令牌。
2. 统一基础组件尺寸、圆角、Focus 和状态变体。
3. 重构一级侧栏、根布局、PageHeader 与滚动边界。
4. 以今日工作台、创作资产和设置页作为三类模板试点。
5. 迁移草稿箱、写作模板、创作任务、待响应和数字人口播。
6. 抽取信息源壳并迁移所有信息源页面。
7. 清理页面内硬编码颜色、原生控件、手写弹窗和重复布局。
8. 完成暗色模式与响应式视觉验收。

详细任务拆分在设计规范审核通过后另行编写实施计划。

## 16. 验收标准

### 16.1 自动检查

- 前端单元测试、类型检查和生产构建通过。
- 静态检查不再发现浏览器原生 `prompt`、`confirm`、`alert`。
- 业务页面不直接使用已被语义令牌覆盖的硬编码主色。
- 页面内部不再重复根布局的侧栏偏移或视口高度。

### 16.2 交互检查

- 键盘可访问所有主要操作。
- Dialog 打开后焦点被约束在 Dialog 内，关闭后返回触发点。
- 表单校验、提交失败和局部重试均保留用户上下文。
- 创作资产新增、编辑、删除、Markdown 编辑和多媒体双击预览正常。
- 草稿创作、素材选择、工作流、发布和真实发布能力不回退。
- 信息源筛选、订阅、采集、字幕任务和 X 素材筛选入口不回退。

### 16.3 视觉检查

- 对今日工作台、YouTube、X、草稿箱、创作资产和设置页进行截图验收。
- 覆盖 Light / Dark、1440×1000、1280×800 和 1024×768。
- 对照已确认的“智性靛蓝”方案检查色彩、层级、间距、栏宽、状态和 Dialog。
- 通过真实浏览器检查响应式布局、滚动边界、控制台错误和主要操作路径。

## 17. 已确认决策

- 选择 A · 智性靛蓝。
- 靛蓝负责主要操作，青色负责采集与数据，紫色负责 AI。
- 使用中等密度和五级字体体系。
- 全站归并为五类页面模板。
- 创作工作台保持约 25% 列表与 75% 编辑器。
- 桌面端不使用业务侧边抽屉，业务配置统一使用 Dialog。
- 彻底移除浏览器原生输入与确认弹窗。
