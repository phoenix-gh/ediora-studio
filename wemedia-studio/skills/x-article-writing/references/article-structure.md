# X Article 结构

## 共同骨架

一篇 Article 只推进一个核心判断。按以下顺序组织，但不要把阶段名称原样写成小标题：

1. **开场承诺**：说明发生了什么、核心判断是什么、读者为什么值得继续读。
2. **必要背景**：只补理解后文必需的概念、时间和上下文。
3. **证据展开**：用原始事实、数字、案例或来源原话支撑判断，并解释证据意味着什么。
4. **限制与反面**：交代证据边界、可能的反例以及尚不能确认的部分。
5. **读者价值**：提供可复用的框架、步骤、清单、对比或决策方法。
6. **收束**：回到核心判断，给出自然的下一步；没有真实下一步时不要硬加 CTA。

段落之间必须有推进关系。删除只是在换词重复结论的章节。

## 按内容选择形态

### 新闻或产品发布

发生了什么 → 最重要的变化 → 对目标读者的影响 → 仍不确定的部分 → 如何继续观察。

不要把官方宣传改写成已经被独立证明的事实。

### 机制或行业分析

表面现象 → 核心机制 → 支撑证据 → 影响对象 → 边界与反例 → 判断框架。

机制推断必须明确依据，不把相关性写成因果。

### 教程或 SOP

可获得的结果 → 前置条件 → 最短可行步骤 → 容易失败的位置 → 验证结果的方法。

步骤必须来自已有素材或可靠工具结果；不凭经验想象产品界面和功能。

### 案例复盘

真实背景 → 采取的动作 → 可验证结果 → 为什么有效或失败 → 可迁移部分 → 不可复制条件。

没有完整证据时写“案例显示”而不是虚构当事人的内心和过程。

### 观点文章

明确判断 → 最强依据 → 可能反对意见 → 回应与让步 → 对读者的实际意义。

鲜明不等于绝对；保留事实允许的复杂度。

## 篇幅决策

篇幅由信息量决定，不用固定字数填充。每一节至少完成一个新任务：提供证据、解释机制、处理反例或帮助行动。若删除一节不影响理解，就删除它。
