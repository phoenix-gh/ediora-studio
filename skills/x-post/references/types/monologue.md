# types/monologue.md：独白/思考帖

**先读 skeleton.md 和 voice-MK.md，再读本文件。**

独白帖 = 你的观察、你的思考、你的判断。**不是教程，不是科普，是"我看到 X，我想到 Y"。**

---

## 取材规则

### 适合做独白帖的素材

- **你观察到的某个现象的趋势/规律**（"最近发现 ...）
- **你对一件常见事物的不同看法**（反共识但有依据）
- **你做了某件事之后的反思**（不是结果汇报，是"做完之后想到了什么"）
- **你对一个概念/分类的重新拆解**（"其实有两种 X..."）

### 不适合做独白帖的素材

- 纯情绪发泄（写日记可以，发推前先问"读者能拿走什么"）
- 没有具体观察支撑的纯抒情
- 已经被讨论烂了的老观点（如果要写，必须有新角度）

---

## 独白帖的标准骨架

```
[钩子句]：[现象 / 观察] + [一个判断词]
（用 skeleton.md 的"反差/反直觉"或"立场宣示"机制）

[1 段]：把这个现象描述清楚。
（具体例子 > 抽象描述。最好有 2-3 个并列例子。）

[1-2 段]：你怎么看？为什么会这样？
（这是独白帖的核心——不是描述，是解释。）

[结尾]：开放式提问 三种结尾里最适合独白的。
（"你怎么看？" 不是水的，是真问。）
```

**和教程/科普的关键区别**：独白帖要有**清晰的"我"的视角**。**第一人称是允许且推荐的**。但不要变成自传——"我"是观察者，不是主角。

---

## 钩子模板（独白类）

### 模板 1：观察 + 判断
```
[现象] 有 [缺点/争议]，但 [反直觉的事实]。
```
例（宝玉）："侧边栏会话有很多诟病，但用户已经习惯了。"
适合：你想讨论一个被低估或被高估的事物。

### 模板 2：分类拆解
```
现在 [领域] 有两类主流 [X]：
```
例（宝玉）："现在 Agent 产品有两类主流交互..."
适合：你看到了一个被混为一谈的事物，想给出新分类。

### 模板 3：直接亮观点
```
[一个明确的观点句]。我想说说为什么。
```
适合：你有非常明确的立场。

### 模板 4：反思型
```
做完 [X] 之后，我意识到 [反直觉的发现]。
```
适合：基于具体经历的反思。

### 模板 5：发问型
```
有个问题我想了很久：[一个具体的问题]？
```
适合：你的思考还没有结论，想跟读者一起想。

## 独白帖最容易翻车的点

1. **变成抱怨**：通篇都在说"现在的 X 都不行"
   → 救：必须有一个具体的"那么应该怎样"，哪怕只是初步设想

2. **没有具体支撑**：空对空地议论
   → 救：第二段必须有具体例子，至少 2 个

3. **结尾烂尾**：写完观察就停了
   → 救：独白帖最适合"开放式提问"结尾，强制用一句真问题收尾

4. **太想给答案**：把独白写成结论
   → 救：留出"还没想清楚"的空间。提问比给结论更有讨论空间。

5. **第一人称太多**：每段都"我觉得""我认为"
   → 救：第一人称用 1-2 次足矣。其余用陈述。

## 真实案例参考（宝玉的"侧边栏 Agent 交互"）

```
侧边栏会话有很多诟病，但用户已经习惯了。

现在 Agent 产品有两类主流交互：

第一类是左边是对话列表，右边是代码或者文档，代表性的是 Codex、Cursor 的 Agent 模式

第二类是左边像传统软件，Agent 对话在右边，比如 GitHub Copilot

第一类是 Agent 为中心，用户主要操作是通过对话指挥 AI Agent，用户去手动修改为辅助，
所以对话为主。这也是为什么像 Cursor 会在原来 IDE 之外新造一个 Agent 模式，
Codex Desktop 甚至连文件编辑都不支持。

第二类是人操作软件为主，Agent 为辅助，借助 Agent 去做一些微调，所以是在不改变原有
操作基础上加个侧边栏。

也有一些软件想全都要，既想要 Agent 对话，又想要保留原有的软件操作，结果是交互很乱。

如何设计好 Agent 的交互还很新，有很多探索空间，但是你的软件是 Agent 为中心还是
Agent 只是辅助，这个得先想清楚，想清楚这点才能做好后续的交互设计。

你怎么看？
```

**拆解**：
- 钩子：模板 1（观察 + 反差判断）
- 第 1 段：分类引出
- 第 2-3 段：两类的具体例子（用具体产品名锚定）
- 第 4-5 段：两类背后的设计哲学（解释为什么）
- 第 6 段：第三类（想"都要"）的失败
- 升维段：从具体设计上升到设计哲学
- 结尾：经典开放式提问"你怎么看？"
