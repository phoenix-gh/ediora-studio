# types/joke.md：段子帖

**MK 自己写段子，凭感觉。**

这个文件只给模板和结构启发。**Claude 不要尝试写完整段子**——你的笑点跟 MK 的笑点不一样，硬写大概率尴尬。你的工作是：

1. 给 MK 几个结构模板，让他对照着想
2. 如果他写了草稿，帮他**精修**（改字数、调节奏、删废话），不替他改笑点

---

## 段子的几种基本结构

### 结构 1：反差三段式
```
[预期] → [真实] → [更尖锐的真实]
```
经典模式。前两段递进式反差，第三段把刀子扎深一点。

### 结构 2：自嘲 + 升维
```
[一件丢人的事 / 一个糗事] → [其实大家都这样 / 这事映射了某个普遍现象]
```
把私人糗事变成普遍共鸣。

### 结构 3：错位类比
```
A 的人都在做 B → 就好像 X 的人都在做 Y
```
用一个意外的类比让人发笑。

### 结构 4：定义重塑
```
所谓 [A]，就是 [一个让人意外的重新定义]。
```
经典格式。简短，犀利，转发率高。

### 结构 5：列表 + 反转
```
做 X 需要：
1、[正常的]
2、[正常的]
3、[完全不正常 / 真相]
```
前两条铺垫，最后一条揭穿。

### 结构 6：对话式
```
A: [一个普通问题]
B: [一个反差回应]
A: [崩溃 / 反应]
```
适合短帖，节奏感强。

### 结构 7：吐槽式
```
[具体场景] + [让人共鸣的吐槽]
```
不需要技巧，就是把大家心里有但没说的话讲出来。但要**具体**——"上班好累"不是段子，"周一早会十点改方案，下午两点说算了" 才是。

---

## 段子帖的注意事项

### 1. 字数要短
段子的力度跟字数成反比。**最佳长度 50-150 字**，超过 200 字基本就不好笑了。

### 2. 不要解释笑点
"这就是为什么 ..." 一旦你开始解释，段子就死了。让读者自己 get 到。

### 3. 避开"段子腔"
- ❌ "今天发生一件好笑的事"
- ❌ "笑死了" / "笑不活了" / 哈哈哈
- ❌ "就这样"

这些是脱口秀演员的开场词，发到 X 上廉价。

### 4. emoji 可以适当用
段子帖是 skill 里**唯一允许 emoji 稍微多一点的类型**。但也别堆。1-2 个画龙点睛即可。

### 5. 真实感是命
段子最怕"AI 编出来的"。**最好的段子都是真事**，或者基于真观察。MK 写之前先问自己："这事真的发生过 / 真的能发生吗？"

## Claude 在段子帖里能做什么

### 你能做的
- 给 MK 一个结构（"用对话式还是反差三段式？"）
- 帮他压缩字数（"这条 180 字，建议砍到 120 字以内，砍这两段：...")
- 帮他找一个更具体的细节（"'周一开会'太泛，是 9 点早会还是 11 点？"）
- 帮他检查节奏（最后一句的"刀"够不够利）

### 你不能做的
- 替他想笑点
- 加你认为"会更好笑"的内容（你不懂他的笑点）
- 给段子写"升维总结" —— 段子不要升维，升维就死了

---

## 如果 MK 直接说"帮我写个段子讲 X"

这是 Claude 该警惕的时刻。**不要假装能写**。回应方式：

> "段子的笑点你比我准。我可以给你 3 个结构模板，你挑一个，把素材填进去给我看初稿，我帮你调字数和节奏。
> 
> 模板 A：反差三段式 ...
> 模板 B：定义重塑 ...
> 模板 C：列表反转 ...
> 
> 哪个适合你想表达的 X？"

这是诚实的协作方式。
