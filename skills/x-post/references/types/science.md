# types/science.md：科普 / 解读帖

**先读 skeleton.md 和 voice-MK.md，再读本文件。**

科普帖 = 把一个事件、一篇论文、一个技术概念，用普通人能理解的方式讲清楚。
**不是新闻搬运，是"我读完之后帮你提炼了精华"。**

---

## 取材规则

### 适合做科普帖的素材

- **新发布的论文/技术博客**（解读 > 转发）
- **行业事件**（迁移、开源、收购，背后有解读价值）
- **一个被误解或被低估的概念**（"很多人以为 X 是 Y，其实是 Z"）
- **跨领域的现象**（用 A 领域的视角解释 B 领域的事）

### 不适合做科普帖的素材

- 已经被各大媒体翻译报道过的新闻（除非你有独特视角）
- 你自己也没读懂的论文（千万别强写）
- 太专业、读者基础严重不够的内容（要么科普先决概念，要么放弃）

---

## 科普帖的标准骨架（最长，最考验功力）

```
[钩子句]：[主体] + [发布动作] + [一个评价词，揭示张力]

[1 段]：必要的背景注释（用【注：】括号格式）。
（如果主角不是大众熟知的人/物，必须注释。）

[1-2 段]：事件本身的具体经过 / 论文核心发现。
（用时间线或数字推进。）

[1-2 段]：机制 / 原因 / 内在逻辑。
（这是科普帖最有价值的部分——告诉读者"为什么会这样"。）

[1 段]：解决方案 / 后续 / 或者争议。
（如果适用。）

[结尾]：升维总结。
（科普帖最适合"升维"结尾——把具体事件拉到普遍道理。）
```

---

## 钩子模板（科普类）

### 模板 1：发布事件 + 评价词
```
[机构 / 人] 发了 [东西]，[评价词] [简述张力]。
```
例（宝玉）："OpenAI 发了一篇技术博客，认真调查了一个荒诞的问题：..."
适合：有具体发布事件作为锚点。

### 模板 2：宣布动作 + 反差
```
[人 / 公司] 宣布 [动作]，[一个反直觉的细节]。
```
例（宝玉）："Mitchell Hashimoto 宣布，他的开源终端模拟器 Ghostty 将从 GitHub 迁出。"
适合：事件本身有反差或情感张力。

### 模板 3：现象观察
```
[一个观察到的现象]，[一个让人停下的问题]。
```
适合：没有具体单一发布事件，但有可观察的趋势。

### 模板 4：尴尬的问题
```
[领域 / 圈子] 一直有个 [越来越尴尬 / 长期没解决] 的问题：[问题描述]。
[今天 / 最近] [谁] 试图解决它。
```
例（宝玉）："科大、新加坡国立、牛津等十余所高校联合发了一篇 88 页的综述，试图解决一个越来越尴尬的问题..."
适合：综述类、立场类论文，或者"标准之争"类事件。

## 变体结构：先捧后杀（反转式）

科普帖不只有"客观解读"一种调性。当素材本身有"看起来很美但实际有坑"的张力时，可以用**反转式结构**：

```
[钩子句]：用判断型/事实型开头，把事情说得很诱人

[1-2 段]：铺陈好处——数字好看、门槛低、逻辑简单
（让读者产生"这生意不错"的感觉）

[1 段]：转折信号——"但问题就出在..." / "然而..."

[2-3 段]：揭示风险——价格战、灰色地带、合规风险、不可持续性
（用具体案例和从业者原话增加可信度）

[结尾]：升维——从具体事件拉到普遍规律
（如"囚徒困境"、"窗口期倒计时"等）
```

**适用场景**：行业揭秘、创业机会分析、套利模式解读
**关键**：前面的"捧"要足够真实（数据、逻辑都站得住），后面的"杀"才有冲击力。不能为了反转而反转。

---

## 科普帖最容易翻车的点

1. **没有注释，读者不知所云**
   → 救：第一次出现专有名词 / 人名时，立刻【注：】解释

2. **机制部分跳步**：直接给结论，没解释怎么得到的
   → 救：机制段必须用"为什么 → 因为 → 所以"的因果链

3. **变成长篇翻译**：把原文直接搬过来加点中文
   → 救：永远问"如果让我用 5 句话告诉朋友这件事，我会怎么说？"那 5 句话才是骨架

4. **结尾止于事实**：报道完就完了
   → 救：必须有升维段。问自己"这件事真正有意思的是什么？"

5. **忽略反直觉细节**：把最有趣的细节藏在中间
   → 救：找到最反直觉的 1-2 个细节，提到前面

## 真实案例参考（宝玉的"哥布林"那条）

```
OpenAI 发了一篇技术博客，认真调查了一个荒诞的问题：为什么他们的模型越来越爱说
"哥布林"（goblin）和"小精灵"（gremlin）？

事情最早在去年 11 月 GPT-5.1 上线后被注意到。用户反馈模型说话太过自来熟，
内部一查，发现包含"goblin"的对话比之前暴涨了 175%，"gremlin"涨了 52%。
当时觉得比例还小，没太当回事。

几个月后 GPT-5.4 上线，哥布林彻底泛滥，用户和员工都受不了了。OpenAI 这才认真追查，
最终锁定了罪魁祸首：ChatGPT 的性格定制功能。

ChatGPT 有八种可选性格，其中一种叫"Nerdy"（极客风）。训练这个性格时，奖励模型被
设定为鼓励"俏皮、有趣的表达"，结果无意中给了包含奇幻生物比喻的回复更高的分数。
模型很快学会了一个捷径：提到哥布林就能拿高分。

[... 中间略 ...]

【注：tic 原本是医学术语，指不自主的重复动作或发声，OpenAI 在这里借用来形容模型养成
的不受控语言习惯。】

[... 修复方案段 ...]

这篇博客表面上是讲一个好笑的 bug，底下其实揭示了一个 AI 训练的核心难题：你给模型
的每一个微小的奖励信号，都可能在你不知道的地方被放大和泛化。一个只针对 2.5%
用户的性格训练，最终污染了整个模型的语言习惯。
```

**拆解**：
- 钩子：模板 1（发布 + 评价词"荒诞"+ 直接抛核心问题）
- 时间线推进（去年 11 月 → 几个月后 → 今年 3 月）
- 机制段（为什么会这样 → 因为奖励信号 → 所以模型学会捷径）
- 数据具体（175%、52%、3881%）
- 注释（tic 的医学术语来源）
- 升维结尾（从一个 bug 升到 AI 训练的核心难题）
