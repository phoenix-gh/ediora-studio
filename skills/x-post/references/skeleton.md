# skeleton.md：宝玉式叙述骨架

这是 MK 想模仿的底层结构，提炼自 @dotey（宝玉）的 X 帖子。
**注意：骨架是骨架，语气是 voice-MK.md 的事。这里只规定"怎么搭"，不规定"怎么说"。**

---

## 一、开头公式（最重要）

**模板：`[主体] + [动作] + [钩子词]`**

每条帖子的第一句话，必须包含一个让人停下滑动的"钩子词"——一个评价性的、带画面感的、暗示着故事张力的词。**没有钩子词的开头就是新闻稿**。

### 钩子词清单（按情绪分类）

**反差/荒诞类**：荒诞、尴尬、反常识、出人意料、讽刺、戏剧性
**强度类**：彻底、终于、暴涨、飙升、泛滥、罪魁祸首、爆发
**时间张力类**：酝酿了好几个月、过去一个月、连续 X 天、用了 18 年
**判断/态度类**：不错、值得、可惜、犹豫、坦白说、说实话
**悬念类**：一个 [形容词] 的问题、一个让人 [动词] 的现象、一件事

### 实战例子

```
[主体]                  [动作]    [钩子词]
OpenAI                  发了      一篇技术博客，认真调查了一个【荒诞的】问题
Mitchell Hashimoto      宣布      ……他【酝酿了好几个月】
科大、新国立等高校      发了      88 页综述，试图解决一个【越来越尴尬的】问题
```

### 反例（不要这样开头）

❌ "今天给大家分享一个工具" —— 没有钩子词，没有主体动作
❌ "AI 圈又爆出新动态" —— 钩子词太泛、缺主体
❌ "🚀 重磅！" —— emoji 和惊叹号代替不了内容钩子

## 二、段落规则

### 1. 双空格换行（X 平台招牌排版）

每段之间用 X 平台的双空格强制换行。**不是 Markdown 空行**，是字面意义的两个空格 + 回车。

### 2. 每段 2-4 句

短段呼吸感强，长段读起来累。如果一段超过 5 句，找逻辑断点拆开。

### 3. 每段必须有信息增量

每段要么给一个新事实，要么给一个新判断。**没有信息增量的段落一律删除**，包括：

- 过渡句（"接下来我们看看……"）
- 总结性废话（"由此可见……"）
- 客套话（"其实这个问题很复杂"）

### 4. 段落之间不靠连接词

不要用"首先 / 其次 / 此外 / 最后"撑结构。逻辑应该让段落本身的内容自然推进。如果非要"列举"，用数字或换行视觉区分。

---

## 三、注释括号（技术教育者的招牌）

**当你提到读者可能不熟的概念、人名、术语时，用括号【注：...】当场解释。**

### 例子

```
Mitchell Hashimoto 宣布……
【注：Mitchell Hashimoto 是 Vagrant 和 Terraform 的创造者，HashiCorp 联合创始人，开发者社区的标志性人物。Ghostty 是近两年热度很高的现代终端模拟器。】
```

```
……都被查出是同一机制产生的"tic词"（语言习惯性抽搐）。
【注：tic 原本是医学术语，指不自主的重复动作或发声。】
```

### 何时用注释

- 提到一个人名，但读者可能不知道他/她是谁 → 注释
- 用了一个英文术语（borrowed term）→ 注释中文含义
- 用了一个领域黑话 → 用大白话翻译一遍
- 用了一个隐喻或借喻 → 解释来源

### 何时不用

- 提到太常见的东西（OpenAI、ChatGPT、GitHub）→ 不需要
- 注释比正文还长 → 重写正文，别靠注释撑

## 四、中段结构（三选一）

视题材选一种。**不要混用**。

### 结构 A：时间线推进型

适合：科普、事件解读、案例分析

```
去年 11 月 ...
几个月后 ...
今年 3 月 ...
但 ... 在找到根因之前已经 ...
```

时间词不一定精确，能用"过去一个月""不久前""最早"也行。**关键是有时间感**。

### 结构 B：观点对照型

适合：教程、独白、对比分析

```
现在有两类主流 [X]：

第一类是 ……
代表性的是 ……

第二类是 ……
比如 ……

第一类是 ……
第二类是 ……

也有一些想全都要 …… 结果是 ……
```

对照不一定二分，三分四分都行。**关键是结构清晰可视**。

### 结构 C：先捧后杀型

适合：产品评测、工具发布、行业热点点评。MK 明确偏好的叙事结构——先让读者觉得这是个好东西/好机会，再反转揭示风险或代价。比纯科普/纯批判更有吸引力，因为读者先产生了兴趣再被泼冷水，冲击感更强。

```
[开头钩子：这个东西真的很强/很有野心/很有前途]
[列举 3-4 个亮点，用具体数据支撑，让读者觉得"哇不错"]
[转折一句："但" / "问题是" / "只是"，节奏要快]
[揭示代价/局限性，同样用数据和事实支撑]
[结论：利弊权衡 或 一个犀利的反问]
```

**关键节奏**：正面段和负面段的篇幅大致对等（各 40% 左右），不要前半段捧了 80% 然后最后两段草草收杀。读者会觉得被骗。也不要反过来（先杀后捧），那叫"洗地"。

实战示例框架（Grok Build CLI）：
- 捧：一行命令安装、8 Agent 并行、Arena Mode、Local-first
- 杀：$300/月天价、连 Grok 自己说太贵、256K 上下文最短、最晚入场

## 五、结尾（三选一）

**绝对不要平淡收尾**。三种结尾任选其一：

### 结尾 1：升维总结

把具体事件拉到一个普遍道理。

```
（哥布林那条）
这篇博客表面上是讲一个好笑的 bug，底下其实揭示了一个 AI 训练的核心难题：
你给模型的每一个微小的奖励信号，都可能在你不知道的地方被放大和泛化。
```

```
（Hashimoto 那条）
他说，一个每天都会把你挡在外面几个小时的平台，已经不适合做严肃的开发工作了。
```

升维的关键句式：
- "表面上 ... 底下其实 ..."
- "这件事真正有意思的是 ..."
- "从 X 到 Y，其实是 ..."

### 结尾 2：开放式提问

适合独白、有争议的话题。

```
你怎么看？
```

```
世界模型的终局，是越来越大的神经网络，还是终究要回到可编辑的符号规则？
```

提问要**真问**，不要用"你觉得呢？"这种敷衍式提问。提问应该：
- 是文章核心张力的延伸
- 没有标准答案
- 能引发读者真实表态

### 结尾 3：冷知识彩蛋

适合教程、轻松话题。

```
顺便说一下：Ralph 这个名字的来源是《辛普森一家》那个爱重复同一句话的小孩 Ralph Wiggum pattern。
```

彩蛋要：
- 真的是冷知识（读者大概率不知道）
- 跟主题相关（不是硬塞）
- 用"顺便说一下"或"题外话"领起

## 六、用词偏好（骨架级别）

**这一节是骨架的一部分，但具体词汇风格属于 voice。这里只列骨架级的硬性要求。**

### 1. 动词要画面感

弱：增加了 → 强：飙升 / 暴涨
弱：减少了 → 强：消退 / 退潮
弱：包含 → 强：塞进 / 嵌入
弱：解决了 → 强：把 X 拉到同一张地图上

### 2. 引用关键短句要双引号

只引最有冲击力的几个字，不要长段引用。

```
博客里教你怎么把抑制指令去掉，"让小精灵们自由奔跑"。
```

### 3. 数字要具体

不要"很多""不少""暴涨"。要"175%""3881%""18 年""88 页"。

### 4. 不堆 emoji

整篇帖子最多 0-1 个 emoji，且只在段落开头当视觉锚点（且通常不必）。**默认 0 个**。

---

## 七、信息密度自检

写完一稿后，逐段问自己：

- 这段如果删了，后面的段还能站住吗？站得住 → 删。
- 这段是给了"事实"还是"判断"？两者都没有 → 删。
- 这段在重复前面说过的东西吗？是 → 合并或删。

**信息密度是宝玉骨架的灵魂，没有它，骨架就是空架子。**
