# formatting-x.md：X 平台排版规则

**X 是字数受限的平台，但 X Premium 用户已经可以发长帖。MK 应该是 Premium 用户**（如果不是，告诉 Claude，按非 Premium 处理）。

---

## 字数

### 单条帖子
- **非 Premium**：280 字符（中文约 140 字）
- **Premium**：可达 25,000 字符
- MK 默认按 Premium 处理，**单条目标长度 100-200 字（中文）**
- MK 偏好精炼短帖，超过 200 字应主动问是否要压缩
- 超过 2000 字应考虑拆 thread

### Thread
- 每条之间留有承上启下的关联
- 每条单独看也能立得住（防止只读到中间一条的人完全懵）
- 总条数 3-15 条最佳，超过就考虑改成长文

## 排版细节

### 1. 段落分隔：双空格 + 换行

X 不渲染 Markdown 空行。两段之间需要：

```
第一段最后一句。[两个空格][换行][换行]
第二段第一句。
```

视觉上呈现出空一行的效果。**这是宝玉骨架的视觉招牌**。

### 2. 不用 Markdown 语法

- ❌ 不用 `**加粗**`（X 不渲染）
- ❌ 不用 `## 标题`（X 不渲染）
- ❌ 不用 `- 列表`（显示为文字"- "前缀，难看）

如果一定要列表/对照，用：

```
第一类是 ...
第二类是 ...
```

或者数字：

```
1、...
2、...
3、...
```

注意中文用"1、"，不用"1."。

### 3. 数字与单位

- 中文数字 + 阿拉伯数字混用：常用阿拉伯数字（"18 年"、"175%"、"88 页"）
- 大数：可用"万""亿"（"70 万开发者"）
- 百分比：直接用 % 符号（"3881%"）

### 4. 引号

- 中文引号 `""`，不用英文 `""`
- 引用关键短语用引号，引用整段用换行 + 缩进或注明来源

### 5. 链接

- X 会自动把 URL 缩短并以缩略卡片显示
- 链接放在帖子末尾，不要插在句子中间
- 如果不希望显示卡片，加空格或断行隔开

### 6. emoji

- **默认 0 个**
- 极少数情况可用 1 个，只在段落开头当视觉锚点
- 永远不要堆叠（"🚀🔥💯"）

## Thread 拆分原则

### 什么内容适合拆 thread

- 单条超过 2000 字
- 有明确的"步骤""阶段""维度"分隔
- 想让每个分点都能被单独转发/引用

### 什么内容不适合拆 thread

- 论证一个观点（拆开后逻辑断裂）
- 讲一个故事（拆开后失去连贯感）
- 内容本身没那么多——硬凑 thread 是 X 上的常见 AI 味

### 拆分模板

**第一条**（钩子 + 承诺 + 引导）：
```
[钩子句]

[2-3 句话说清楚 thread 要讲什么、读者能得到什么]

接下来按 [N] 个 [维度] 来说。
```

**中间每条**：
- 有自己的小钩子（不一定是"钩子词"，可以是序号 + 主题）
- 信息独立完整
- 结尾不留尾巴（让人想看下一条 ≠ 留半句不说完）

**最后一条**（升维或行动号召）：
- 用 skeleton.md 的"升维总结"结尾
- 或者一个明确的行动指引（"想了解更多看 [链接]"）
- **不要写"以上就是全部"** —— 这是 AI 味重灾区
